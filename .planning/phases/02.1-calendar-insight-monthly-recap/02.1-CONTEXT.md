# Phase 2.1: Calendar Insight and Monthly Recap - Context

**Gathered:** 2026-06-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver homepage-level explanations for calendar markers and prediction math, plus a copyable monthly recap. This phase does not change cloud data models, medical prediction algorithms, room sharing, or settings export behavior.

</domain>

<decisions>
## Implementation Decisions

### Homepage insight surface
- **D-01:** Add in-page sheets on `pages/index/index.*`, not native modal dialogs, to match the existing themed day action and month-jump sheets.
- **D-02:** Keep marker meanings explicit: today, period, memory, prediction, holiday, and adjusted workday must have distinct names and explanations.
- **D-03:** Day detail should explain marker meanings before listing period/memory records so users understand why a date looks highlighted.

### Prediction explanation
- **D-04:** Show prediction as a plain-language explanation: estimated date, range, average cycle, average duration, confidence, and ignored outlier count.
- **D-05:** Wording must avoid medical certainty; prediction is an estimate based on recent records.

### Monthly recap
- **D-06:** Monthly recap is homepage-only for this phase: current selected month, current records, happy-time memories, and next prediction.
- **D-07:** Recap should be copyable to clipboard; no image generation, PDF export, cloud persistence, or sharing integration in this phase.

### the agent's Discretion
- Exact visual spacing and copy tone inside the existing Aurora Bloom style.
- Whether the interpretation logic lives in a new utility module or existing helpers, provided it is testable and does not bloat the page file.

</decisions>

<specifics>
## Specific Ideas

- User selected the second recommendation ("日历更懂人") and the third recommendation narrowed to monthly recap only.
- Web research favored three small product patterns: clear marker legend, transparent prediction explanation, and gentle recap/export behavior.

</specifics>

<code_context>
## Existing Code Insights

### Reusable Assets
- `cycle.predictNextPeriod(periods)` already returns `nextDisplay`, `rangeDisplay`, `avgCycle`, `avgDuration`, `confidenceText`, `usedCycleCount`, and `ignoredCycleCount`.
- `cycle.decoratePeriod(period)` already maps flow and symptoms to display labels.
- `util.buildCalendarDays(...)` already marks `isToday`, `isPeriod`, `isMemory`, `isPredict`, `isHoliday`, and `isWorkday`.

### Established Patterns
- Homepage sheets use `day-sheet-mask`, `day-action-sheet`, `sheet-head`, `sheet-actions`, and `catchtap="noop"` to avoid native modal styling.
- Existing tests prefer pure helper functions plus lightweight source contract checks for WXML/WXSS/page wiring.

### Integration Points
- New interpretation helper should be imported by `pages/index/index.js`.
- Day detail should add `selectedDayDetail.meanings`.
- Monthly recap copy should use `wx.setClipboardData`.
