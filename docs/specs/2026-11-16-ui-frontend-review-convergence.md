# UI 与前端评审收口：记录正确性、首页状态、配对与界面收拢

**Issue:** [#200](https://github.com/Baker4real/minmin-calendar/issues/200)

## Problem Statement

两个人打开这个小程序，要的是：相信日历上写的事实，扫一眼就知道「现在什么情况」，对方加入前后都能把房间连上，记一条、改一条时不出错。2026-11-15 的全项目 UI / 前端评审（基线 HEAD 0cae38f；启发式 27/40，技术审计 14/20）结论是界面体系扎实：标记语义、失败处理、token 和护栏都成体系，没有需要整套换掉的部分。但记录正确性、首页信息层级、配对、确认交互和前端实现上还有一批问题。本规格把评审里推荐做的和可以做的全部收进来，只排除评审明确不建议的方向。

### 目标与已确认选择

- 范围：评审中推荐做的和可以做的全部收入；评审明确不建议的方向不做（见 Out of Scope）。
- 多机型与兼容性测试按维护者 2026-11-06 的决定不做。运行态只在模拟器当前机型上验收。
- 要看运行态结果才能选的项，写成判定规则，实现方照规则自己选。
- 与现行 ADR、CONTEXT.md、DESIGN.md 或动效文档冲突的改动，先改文档或追加 ADR 补充，再改代码。

### 已知事实与约束（2026-11-16 在 HEAD 0cae38f 回源核对）

- **草稿**：所有新建记录共用一个草稿键。打开编辑会话时，草稿字段（含日期）盖在路由带来的值上。界面只显示一行「已恢复上次未完成的输入」，没有放弃入口。
- **进行中经期**：只要有进行中经期，任何日期的经期入口都返回这一条。当日弹层的按钮文字只看这一天是不是经期日，所以在别的经期日上，「编辑这次经期」打开的是进行中那条。ADR 0007 现行写法是「新经期入口先重开开始日最晚的进行中记录」。
- **原生确认弹窗（五处）**：
  - 删除和解除绑定把确认键设成为深色底调的警示红，落在白底弹窗上约 2.72:1，并有两条测试钉住这个颜色。
  - 平台限制按钮文字最多 4 个字符，ADR 0007 记录过五字按钮被拒。
  - 开始日归属询问（「这一天已有经期」弹窗）把「仍然新建」放在取消键上，回调只看确认键。所以任何不是点确认的关闭，都会新建并保存。
- **读屏**：日期字段和首页月份按钮的读屏名不含当前值。绑定页的错误条没有 alert 角色。
- **首页状态行**：
  - 状态行是 caption 档。
  - 窗口前，状态行和「经期临近」提醒数到不同的锚点，同屏出现两个天数；窗口内，两处是同一句话。
  - 推迟时，状态行没有上限地一直数下去，预测说明也没有推迟版本。
- **配对**：绑定页默认「创建」页签。「发给 TA」只在刚创建那一次出现。邀请卡没有配图。
- **记录 tab**：每次显示都把扁平数组和分组各下发一份，而模板只读扁平数组的长度。刷新失败行里的重试块和行一样高，这是检测器唯一成立的发现。
- **节假日数据**：节假日表止于 2026 年。未发布的年份只按规则显示节日名，没有调休和放假范围。CONTEXT.md「Holiday Data Boundary」要求跨年前更新，上游 2027 年数据已于 2026-11-05 提交。
- **死代码与过期登记**：
  - 一组加载指示样式没有任何模板引用，动效文档仍把它当现役。
  - 兼容路由页的样式里，绝大多数规则没有节点使用。
  - 「当天无记录」空态和一条动作分支走不到。
  - `openLegendSheet` 没有任何绑定。
- **工程现状**：
  - 仓库没有自定义组件、运行时 npm 依赖、darkmode 声明、prefers-color-scheme 查询，也没有触感反馈。跨页共享只靠全局样式和一份极光片段。
  - 页面行为测试用的平台 harness 不支持自定义组件。静态设计护栏直接读各页的 WXML / WXSS。
- **性能数字的来源**：评审子代理在桌面 Node 上用构造数据测得，不是真机数据。

### 关键失效方式

1. **记错事实**：旧草稿把这次点的日期换掉，直接保存就记错了日子。「记结束」带来的「已结束 + 今天」也会被旧草稿盖回去。
2. **卡住**：经期进行中时补记不了更早的经期；同一个弹层里，两个看起来同义的入口打开的是不同的记录。
3. **误操作**：危险确认键看不清；取消键带着业务动作，一返回或误触就多出一条记录。
4. **读不懂现在**：
   - 最要紧的那句话排成了全页最小的字，同屏还有两个不同的天数。
   - 推迟时只剩一个越来越大的数字。
   - 标记的解释藏在两层菜单之外。
5. **配对掉线**：手输房间码进来的 TA，面前最显眼的是「创建」；错过第一次就没有再邀请的路；邀请卡用的是页面截图。
6. **读屏听不到**：听不到字段的当前值，也听不到状态变化。
7. **实现漂移与浪费**：
   - 同一控件有多份实现，已经出现差异。
   - 记录 tab 把全部记录下发两遍。
   - 死代码和过期文档会误导后续改动。
   - 节假日数据有跨年期限。

## Solution

完成后，从用户角度看：

- **草稿**：新建表单只在点的是同一天时才恢复上次没填完的内容。恢复时写明是哪天的内容，并能一键放弃。「记结束」打开时总是带着「已结束 + 今天」。
- **进行中经期**：不再有把人带去别处的按钮。当天已有的记录行就是编辑入口。更早、没被任何记录覆盖的日子可以补记经期，新记录默认已结束。
- **确认交互**：
  - 删除、解除绑定、重新同步、导出、开始日归属询问和分享失败后的选择，都在应用内的深色确认面板里完成。
  - 危险键用项目自己的警示样式，按钮能写下完整的话。
  - 系统返回、点遮罩、下拉都等于取消。
  - 归属询问给出「编辑那条 / 仍然新建 / 取消」三个明确选项。
- **首页状态行**：
  - 状态行是首页唯一的状态句：字号升档，带「›」，读屏名说明点按会打开预测说明。
  - 窗口前、窗口内、推迟、推迟太久、经期中、经期超出预期，各有一句。不再有第二套提醒行。
  - 推迟时点开说明，看到的是推迟版本。
- **标记说明**：左上角「图例」直达标记说明；欢迎条指向它，并且整条可点；「预」、节日、调休的含义句是真正的解释。
- **配对**：
  - 绑定页不预选页签，给两个等权入口。
  - 房间建好后写「房间建好了」。
  - 等 TA 期间，在设置页和首页都能再发邀请。
  - 邀请卡配一张不含经期字样和房间码的静态图。
  - TA 加入后，创建者也看到一次欢迎条。
  - TA 新记的内容，回到首页时亮一次。
- **读屏**：读屏名带上日期和月份的当前值；错误、草稿恢复和状态后果都会被播报。
- **数据下发**：记录 tab、首页和编辑页只下发模板要用的数据；冷启动时，房间校验和记录读取并行。
- **前端收拢**：
  - 重复实现收成一份：共享样式用 `@import`，共享标记用 `template` / `include`。
  - 分段控件、弹层几何、重试行已有的差异统一掉。
  - 死代码和过期登记清掉。
  - 2027 年节假日更新，并有生成脚本。
- **视觉规范**：
  - 清爽密度的色带提到可辨的对比度，完整密度加高对比边线。
  - 首页两个记录入口分出主次。
  - 经量标签改弱态，两级展开 / 收起用同一种颜色。
  - 语义 token、文字透明度档和字号阶梯收拢。
- **判定规则**：只有运行态才能定的项，按本规格的判定规则在模拟器当前机型上定案，并记进验证日志。

## User Stories

### 草稿与记录正确性

1. 作为补记经期的人，我希望新建表单只在我点的是同一天时才恢复上次没填完的内容，以便不会把内容记到别的日子上。
2. 作为被打断后回来的人，我希望恢复提示写明是哪天的内容，并给我「放弃」，以便一键回到这次入口的初值。
3. 作为修改已有记录的人，我希望恢复提示给我「放弃修改」，以便回到已保存的值。
4. 作为点「记结束」的人，我希望表单总是带着「已结束」和今天打开，以便两下完成，不被旧草稿盖回「进行中」。
5. 作为读屏用户，我希望草稿恢复提示被主动播报，以便知道表单里不是空白。
6. 作为在经期第一天开始用的人，我希望能给进行中经期之前、没被记过的日子补记经期，以便把前几个月补上，尽快得到预测。
7. 作为点开上个月经期日的人，我希望弹层里只有打开那一条的记录行，不再有去向不同的「编辑这次经期」按钮，以便改的就是我看的那条。
8. 作为在经期进行中点开更早日子的人，我希望先看到「这次经期还在进行中」的常驻说明和「记结束」，以便知道先做什么。
9. 作为在记录 tab 操作的人，我希望经期按钮写出它真实的去向，以便和首页一致。
10. 作为点了「记结束」的人，我不希望再看到「已有进行中的经期」的提示，以便按钮说的和发生的一致。
11. 作为新建经期的人，我希望选好开始日后，就在下方看到这一天已在哪条经期里，并能「打开那条」，以便保存前就知道。
12. 作为在归属询问里选「编辑那条」的人，我希望这次已填的内容仍留在新建草稿里，以便回来不用重填。

### 确认交互

13. 作为删除记录的人，我希望确认键在深色面板上清楚可辨，并用项目的警示样式，以便不点错。
14. 作为删除记录的人，我希望确认里写明删的是哪条、是谁记的，以便删 TA 的记录前心里有数。
15. 作为新建经期的人，我希望归属询问给出「编辑那条 / 仍然新建 / 取消」三个明确选项，以便误触或返回时不会多出一条记录。
16. 作为安卓用户，我希望用系统返回、点遮罩或下拉关闭确认面板都等于取消，以便没有藏起来的业务动作。
17. 作为解除绑定的人，我希望确认里说清解除后我这边看不到日历、记录还在、以后怎么回来，并显示房间码，以便以后能回去。
18. 作为重新同步房间的人，我希望确认用平常话说清会做什么、不会删记录，以便放心点。
19. 作为导出数据的人，我希望导出确认和分享失败后的选择也在同一种面板里，选项写全，以便看懂每个按钮。

### 首页状态与标记

20. 作为打开首页的 TA，我希望「现在什么情况」那句话是首页最醒目的文字，以便扫一眼就知道。
21. 作为看首页的人，我希望同屏只出现一个天数，以便不去怀疑预测。
22. 作为看首页的人，我希望状态行像其他可点行一样带「›」，以便知道点开有说明。
23. 作为读屏用户，我希望状态行的读屏名说明点按会打开预测说明，以便知道它能做什么。
24. 作为在预测窗口之前的人，我希望状态行说预计哪天开始、还有几天，以便提前准备。
25. 作为在预测窗口内的人，我希望状态行说「这几天可能开始」，记录入口就在下面，以便开始了马上能记。
26. 作为经期推迟的人，我希望状态行在窗口结束后 7 天内说「比预计晚 N 天」，之后改说上次记录哪天开始、可以补记，以便漏记时不被一个越来越大的数字吓到。
27. 作为推迟时点开说明的人，我希望看到原本估在哪天、已经过了几天、开始了或漏记了怎么办，并保留「不是医疗建议」，以便知道下一步。
28. 作为推迟时想记录的人，我希望说明弹层里直接有「记经期」，以便不用退出去找。
29. 作为经期进行中的人，我希望超出预期天数时，状态行补一句比预期多几天，以便记得记结束，又不被一次性提醒打扰。
30. 作为记录还不够的人，我希望每一处说的预测门槛都一样，而且是真实条件，以便知道还要记几次。
31. 作为看日历的 TA，我希望左上角直接有「图例」，以便随时查标记的意思。
32. 作为刚加入的人，我希望欢迎条告诉我以后去哪看图例，并且能点开图例，以便第二次打开也不迷路。
33. 作为点开「预」那天的人，我希望看到「按之前的记录估的，前后几天都有可能」这样的解释，以便明白它不是确定的日子。
34. 作为点开节日或调休日的人，我希望看到这天为什么这样标、数据从哪来，以便不只是把标题重说一遍。
35. 作为在当日弹层里看记录的人，我希望可点的记录行带「›」，和不可点的含义卡看得出区别，以便找到改记录的入口。
36. 作为在首页记录的人，我希望「记经期」是实色主按钮、「记欢乐时光」是次级样式，以便分清主次。
37. 作为用清爽密度的人，我希望经期色带足够显眼，以便一眼看出哪些天是经期。
38. 作为用完整密度的人，我希望色带边界清楚，农历字也照样清楚，以便两样都不牺牲。
39. 作为 TA，我希望对方新记的经期或欢乐时光在我回到首页时亮一次，以便不用口头同步。
40. 作为看本月小结的人，我希望小结有主次、每条欢乐时光单独一行，复制出去也是一行一条，以便读得下去。
41. 作为看预测说明的人，我希望不出现「置信度」这类术语，而是一句平常话，以便看懂估得准不准。
42. 作为用选月面板的人，我希望切换年份后，高亮和标题显示的是真实生效的年月，以便不会误以为已经跳过去了。

### 配对与房间

43. 作为手里只有房间码的 TA，我希望绑定页不预选「创建」，而是给两个等权入口「我来建房间」「我有房间码」，以便不会点错、建出一间空房间。
44. 作为点邀请卡进来的 TA，我希望仍能直达加入，以便一步完成。
45. 作为刚建好房间的人，我希望标题写「房间建好了」，并告诉我把房间码发给 TA，以便知道下一步。
46. 作为建好房间后先进了日历的人，我希望在设置页和首页都能「再发邀请」，以便 TA 没收到时补发。
47. 作为发邀请的人，我希望邀请卡配一张不含经期字样、不含房间码的静态图，以便在会话里不露隐私。
48. 作为创建者，我希望 TA 加入后我也看到一次欢迎条，以便知道已经连上，也看到标记说明。
49. 作为粘贴房间码的人，我希望空格被自动去掉，以便不会被报「房间不存在」。
50. 作为冷启动的已绑定用户，我希望房间校验和记录读取同时进行，以便日历更快出来。
51. 作为遇到校验较慢的人，我希望过一会儿能看到「正在打开日历…」，以便知道不是卡住了。
52. 作为解绑后回到绑定页的人，我希望看到一句怎么回原来房间的说明，以便面前不只是一张全新的卡片。
53. 作为看到房间失效提示的人，我希望提示用平常话说清发生了什么、记录没删、下一步怎么做，以便不慌。
54. 作为重新同步的人，我希望看到同步完成后的结果，而不是中间步骤，以便知道成功了。
55. 作为在两页看房间码的人，我希望设置页和绑定页上的房间码长得一样，以便认得出。
56. 作为加入失败的人，我希望绑定页的错误被读屏主动播报，重试和其他页一样是玫瑰色整行，以便知道可以再试。

### 记录 tab 与编辑页

57. 作为第一次进记录 tab 的人，我希望零记录时先看到引导，而不是一张「0 / -- / --」的卡，以便知道怎么开始。
58. 作为等加载的人，我希望周期概览的数字位置先占好，以便数字出现时页面不跳。
59. 作为看列表的人，我希望经量标签是低噪的弱态，进行中胶囊保持醒目，以便日期和时长不被抢走注意力。
60. 作为翻列表的人，我希望年份和月份两级「展开 / 收起」用同一种颜色，以便不像两种东西。
61. 作为遇到刷新失败的人，我希望重试是一整行玫瑰字、和首页一样，以便同一种状态长得一样。
62. 作为补记经期的人，我希望空的结束日期框写着占位提示，以便保存前就知道要选。
63. 作为填经期表单的人，我希望必填项和「选填」项分在两张卡里，以便知道哪些可以不填。
64. 作为选经期状态的人，我希望状态后果说明紧跟在状态选项后面并被播报，状态选项的读屏名也带上后果，以便选之前就明白。
65. 作为打开一条记录的人，我希望编辑页写明这条是谁记的，以便改 TA 的记录前心里有数。
66. 作为记欢乐时光的人，我希望正文字段叫「内容」而不是「备注」，以便知道这里就是要写的话。

### 1. 草稿（recordCommands 会话）

1. **新建草稿按日期恢复。** 只有路由日期等于草稿里的日期时才恢复。日期不同就不恢复，也不删除；这份草稿由本次会话之后的草稿写入自然覆盖。依据：草稿键按记录身份区分，但「新建」这一个身份对应任何一天，日期是唯一能区分「同一次没写完」的字段。
2. **「记结束」意图下路由优先。** 状态和结束日以路由为准，备注、经量、症状照常恢复。
3. **恢复提示可操作。**
   - 文案：新建写「已恢复 X月X日 没填完的内容 · 放弃」；已有记录写「已恢复上次没保存的修改 · 放弃修改」。
   - 只有「放弃」用玫瑰色（它是唯一可点的部分），说明文字用次要文字色。提示行带 alert 角色。同文的 toast 撤掉，由提示行承担。
   - 点「放弃」：清掉草稿，新建表单回到本次入口的初值，已有记录回到已保存的值，提示行消失。
4. **未改动不写草稿。** 表单与本次初值相同时，隐藏或卸载都不写草稿。草稿只在保存成功或点「放弃」时清除。
5. **选「编辑那条」时保留草稿。** 本次的新建内容留作新建草稿，不再丢弃；回到同一天新建时按第 1 条恢复。

### 2. 进行中经期的入口（periodCoverage、homeCalendarState、记录 tab）

1. **当日弹层详情模式。** 这一天已有经期记录行时，不再显示经期动作按钮，记录行就是编辑入口。经期记录行的读屏名以「编辑这次经期」开头，并带日期范围。
2. **第一步，不改 ADR。** 有进行中经期、所选日早于它的开始日、且不在任何记录范围内时：
   - 当日弹层不给经期按钮，改为与未来日期说明同形态的常驻说明块：「这次经期还在进行中，记了结束才能补记别的」，加一个「记结束」按钮（打开进行中那条，带记结束意图）。
   - 欢乐时光按钮照常显示。
3. **第二步，在 ADR 0007 补充之后。** 上述日子改给「补记经期」，按所选日新建，默认已结束，结束日留空，第一步的说明块随之撤掉。用户在表单里把状态改成进行中时，沿用现有的云端合并重开路径。
4. **记录 tab 的经期按钮与首页同源。** 标签和去向取同一份投影：没有进行中经期时是「＋ 记经期」（今天新建）；有进行中经期时是「经期第 N 天 · 记结束」。
5. **删除「已有进行中的经期，继续编辑它」提示。** 第 1–4 条落地后，它在首页、记录 tab 和记结束入口上都不再有用处，连同 toast 一并删除。

### 3. 确认交互

1. **止血（第一步，可先于面板单独发布）。**
   - 删掉删除和解除绑定两处的自定义确认色，用平台默认色（白底约 5.33:1）。
   - 开始日归属询问只在明确点了取消键时新建，其余关闭方式什么都不做。
   - 同步钉色测试和归属询问的用例。
2. **应用内确认面板（第二步，ADR 0009）。**
   - 属于底部弹层家族：共享模板、共享样式，控制器由 sheetLifecycle 驱动。每页一个。
   - 内容：标题写问题，一句写后果，再加 1–3 个按钮。危险确认用项目的 btn-danger 样式，普通确认用玫瑰主按钮，取消是次级样式。
   - 系统返回、点遮罩、下拉、点 × 都等于取消。减弱动效下即时到位。
   - 读屏的面板名、遮罩名和背景隐藏，与现有弹层保持一致。
3. **迁移六处。**
   - 开始日归属询问：编辑那条 / 仍然新建 / 取消。
   - 删除记录。
   - 解除绑定（文案见第 10 节）。
   - 重新同步房间：「重新从云端读一次你所在的房间，不会删除任何记录」。
   - 导出数据。
   - 分享失败后的选择：重试分享 / 复制成文字 / 取消。

   失败呈现弹出的原生弹窗（知悉、重试、去绑定三类）保留原生。依据：它们只在确认键上执行动作，也没有自定义颜色，原生弹窗的三个缺陷都不涉及它们；要迁移就得每个页面都挂面板，收益小。
4. **删除确认的文案。** 标题是「删除这条经期？」或「删除这条欢乐时光？」。正文依次写：日期范围或日期；配对后写「这条是 TA 记的」或「这条是你记的」；最后写「删除后你们两人的日历里都会移除」。
5. **四字限制的范围。** 面板不再受四字限制，但按钮仍用短动词。平台 harness 里原生确认键的 4 字上限保留，只约束剩下的原生弹窗。

### 4. 首页状态行（提醒行退役）

1. **状态行是首页唯一的状态表达。**
   - 通栏提醒行全部退役：经期临近、这几天可能开始、可能开始的日子已过、经期还未结束。
   - 提醒的已见存储和 homeCalendarState 里的提醒投影一起退役。
   - 依据：从根上消掉同屏两套说法，也一并消掉首屏之外的一次性提醒和「不看视口就记已见」的问题。它与「提醒和状态行同锚点、告知型提醒不带实色按钮」的就地修法互斥，本规格选退役。
2. **状态句。** 由 cycle 产出、homeCalendarState 投影。只陈述事实，不写「很正常」一类判断。

   | 状态 | 状态行文案 |
   |---|---|
   | 经期中 | 「经期第 N 天」；天数超过预期时长时加后缀「· 比预期多 M 天」。预期时长的来源沿用 ADR 0007：用户设置 → 已完成记录的中位数 → 默认五天 |
   | 记录不足 | 第 6 条的统一门槛句 |
   | 窗口前 | 「预计 X月X日 开始」，右侧倒数「还有 N 天」。数到预计开始日，与预测说明同一个锚点 |
   | 窗口内 | 「这几天可能开始」 |
   | 推迟（过了窗口结束日，到窗口结束后 7 天内） | 「比预计晚 N 天」，N 仍从预计开始日算 |
   | 推迟超过窗口结束后 7 天 | 「上次记录 X月X日 开始 · 可以补记」，不再数天数 |
3. **样式与读屏。**
   - 主句用 body-lg 字号加 600 控件字重；倒数放右侧，用 caption 次要色。
   - 行尾加与记录 tab 同款的「›」。
   - 88rpx 行高不变，不动几何账本。
   - 读屏名为「状态句，点按查看预测说明」。
4. **预测说明分状态。**
   - 窗口前和窗口内沿用现版。
   - 两种推迟状态换成推迟版，依次是：
     - 「原本估在 X月X日 前后 N 天，现在已经过了 M 天」
     - 「已经开始了就记经期；漏记了，在日历上点那一天补记」
     - 「根据记录估算，不是医疗建议」
     - 一个「记经期」按钮，去向与首页记录入口相同。
   - 经期中且超出预期时，说明顶部加一句「这次已经 N 天，比预期的 M 天多；结束了就点「记结束」」。
5. **去掉「置信度」。** 改成一句平常话，如「最近几次很规律，估得比较准」。复制出去的小结同样改。
6. **预测门槛只有一处来源（cycle）。**
   - 少于两次开始日：「记两次经期后就能估下次」。
   - 有两次以上但没有可用的间隔：「最近几次间隔差得多，再记几次就能估」。
   - 状态行、记录 tab 空态、预测说明三处都取这一份。

### 5. 图例、欢迎条与当日弹层

1. **「工具」改为「图例」。**
   - 顶栏「工具」改为「图例」，点按直接打开图例，处理函数复用目前没有绑定的 `openLegendSheet`。
   - 工具菜单退役：预测说明从状态行进，本月小结从小结行进。弹层交接只剩这一个调用者，一并删除。
   - 它与「欢迎条写明图例在『工具』里」互斥，本规格选直达。
2. **欢迎条。**
   - 文案带上去处，例如「已和 TA 连上。玫瑰色带是经期，♥ 是欢乐时光，「预」是可能开始的日子。点这里或左上角「图例」随时再看」。
   - 必须在几何账本记的两行之内，按 rpx 字宽静态核算。超出就缩短前半句，不缩字号。
   - 整条可点，点了打开图例。一次性规则不变。
3. **当日弹层的记录行。** 可点的记录行右端加与记录 tab 同款的「›」，保留按压态。含义卡改成无描边的说明块，与记录行拉开区别。
4. **含义句。**
   - 「预」：「按之前的记录估的，前后几天都有可能。」
   - 节日：已公布年份写「法定假日，按官方安排放假」；未公布年份写「节日按历法标出，放假和调休等官方公布后更新」。
   - 调休：「这天是周末，按官方安排调成上班」。
5. **图例指向使用说明。** 图例底部加一句，指向「设置 → 使用说明」。
6. **删掉走不到的代码。** 删除「当天无记录」空态和不存在的 detail 动作分支。
7. **选月面板。**
   - 两个箭头之间的年份是正在浏览的年份；副标题显示当前生效的年月。
   - 月份高亮只在浏览年等于生效年时出现。点月份才同时应用年和月，并关闭面板。
   - 依据：一次跳转只有一次整月提交，延续评审「一次点选」的结论。

### 6. 配对与邀请

1. **绑定卡不预选页签。**
   - 给两个等权的次级入口「我来建房间」「我有房间码」，选了再展开对应内容。
   - 带邀请码进来仍直达加入，并预填房间码。
2. **刚建好房间。**
   - 标题改为「房间建好了」，下一行写「把房间码发给 TA，TA 加入后你们看的是同一本日历」。
   - 「发给 TA」仍是唯一主按钮，沿用 2026-11-03 规格。
3. **邀请图。**
   - 一张 5:4 的静态图（约 500×400，40 KB 以内），不含经期字样、房间码或任何个人信息。
   - 所有邀请分享都用它作 imageUrl。
   - 图片入包，并登记到已跟踪图片的测试。
4. **再发邀请。**
   - 设置页房间卡在等待状态，把「等待 TA 加入」换成「TA 还没加入」，加一个原生分享按钮「再发邀请」。
   - 首页在等待状态时，在欢迎条的槽位显示邀请条：两行，与欢迎条同高。第一行「TA 还没加入」，第二行「发个邀请，TA 加入后你们看的是同一本日历」，右侧是原生分享按钮「发邀请」。配对后撤掉。
   - 邀请条与欢迎条共用同一个账本项，两者不会同时出现。
5. **分享内容按状态返回。**
   - 承载邀请的三个页面（绑定、设置、首页）在等待状态返回邀请卡：路径带房间码，配静态图。
   - 不在等待状态时，首页与设置页隐藏胶囊菜单里的转发；万一触发，只返回不带房间码的普通卡片。
6. **配对三态。**
   - roomRecordsSync 对外给出 waiting / paired / 未知三态。「未知」指列表还没带回配对状态。
   - 首页邀请条只在 waiting 时出现，未知时不出现。
7. **创建者的欢迎条。** 首页观察到 waiting → paired 时，显示一次欢迎条（同一个一次性标记），不再弹「TA 已加入」toast。设置页保留它的 toast。

9. **房间码输入。** 先去掉全部空白再转大写，与启动参数里邀请码的处理一致。
10. **冷启动并行（路线 A，不改启动首屏的定义）。**
    - 绑定页发现本机有房间码时，校验和共享记录加载同时发起；首页显示时并入这条在途加载（ADR 0008：在途加载由所有调用方共用）。
    - 校验结果为未绑定或失效时，走现有的失效路径，丢弃这次加载的结果。
    - 路线 B（有缓存就直接进首页）与之互斥，不做。
11. **校验期间的提示。** 约 800ms 后，在心形下方出现一行说明「正在打开日历…」；校验更快完成时不出现。

### 17. 触感、收录与命名

   - 只在两个时刻各触发一次 `wx.vibrateShort`（type light）：保存确认成功、建房成功。失败时静默。
   - 其他时刻不加。在动效文档登记。
2. **收录。** sitemap 对所有页面 disallow。依据：私密的两人应用，没有可供搜索的公开内容。
3. **命名。** 应用内保留「美少女的日历」，PRODUCT.md 补一句应用内显示名（假设见 Further Notes）。

### 18. 判定规则

所有判定都在模拟器当前机型、替身 Room 上执行。每条的观察结果和选择都写进验证日志。

- **R1 darkmode。**
  - 做法：在 app 配置里临时声明 darkmode，配上明暗两套取同值的主题变量，分别在系统浅色和深色下看三类东西。
    - ① 页面、原生 tabBar 和导航相关颜色，是否与不声明时完全一致。
    - ② 仍是原生的面板（失败呈现弹窗、加载提示；R2 保留原生时还有日期滚轮），在系统深色下是否变深。
    - ③ 原生分享按钮和输入框的默认样式是否变化。
  - 选择：① 一致、② 变深、③ 无变化 → 保留声明，在 DESIGN 登记；任何一项不满足 → 不声明。
- **R2 日期选择。**
  - 做法：在系统浅色下打开三个日期字段的原生滚轮。
  - 选择：
    - 面板是浅色 → 改用自有的日期面板：属于底部弹层家族，内含年 / 月 / 日三列 picker-view，上限是今天，下限沿用现有值，每列和确定键都带含当前值的读屏名，三个字段共用。
    - 面板已经是深色 → 保留原生。
- **R3 滚动穿透。**
  - 做法：分别打开首页 4 个弹层和设置页使用说明，在遮罩和面板正文上下滑，在页顶下拉。
  - 选择：
    - 底层页面跟着滚，或触发了下拉刷新 → 遮罩拦截触摸移动；弹层打开和离场期间用 page-meta 锁住页面滚动；这段时间里下拉刷新不发起同步并立即收起。
    - 都不发生 → 不改。
- **R4 下拉刷新指示。**
  - 做法：在首页和记录 tab 下拉。
  - 选择：
    - 原生加载点在自定义顶栏下可见 → 不改。
    - 被顶栏盖住 → 保留原生下拉；首页用顶栏的同步胶囊表示刷新中；记录 tab 在分段控件下方显示一行「正在刷新」（status 角色），结束即消失。不换成 scroll-view 自带的刷新。
- **R5 吸顶分界。**
  - 做法：在首页向上滚，让内容经过吸顶区下沿，截图取下沿两侧的像素。
  - 选择：两侧 RGB 各通道差都不超过 8 → 在吸顶区底部加一条 1px、白色 8% 的发丝线；否则不改。
- **R6 极光色团。**
  - 做法：截首页首屏，逐个看色团的可见面积。
  - 选择：某个色团在首页被吸顶区和日历卡完全遮住 → 只在首页暂停它的动画，其他页面不变；有露出 → 不改。
- **R7 保存键位置。**
  - 做法：在经期编辑页补记过去的一天，状态选已结束，两张卡全部展开。
  - 选择：
    - 保存键在首屏之外 → 保存 / 删除块固定在底部（含安全区）；文本框获得焦点时隐藏，失焦后恢复。
    - 在首屏之内 → 不改。
- **R8 分享面板返回。**
  - 做法：刚建好房间时，在绑定页点「发给 TA」，然后取消分享。
  - 选择：
    - 绑定页因 onShow 重新校验并自动进了首页 → 加一个「分享中」标记，分享返回后的那一次显示不自动跳转。
    - 没有跳转 → 不改。
    - 模拟器无法复现分享面板 → 按「会跳转」处理（这个标记没有副作用）。
- **R9 字体放大。**
  - 做法：在模拟器里调大微信字体；工具不支持时，记为未验证，不改。
  - 选择：
    - 小程序文字跟着变大，且固定高度的单行盒出现裁切 → 把这些盒改成最小高度并允许换行；日历格内的文字保持单行省略；吸顶占位和几何账本同步调整。
    - 文字不变 → 不改，在 DESIGN 记一句「不随微信字体设置缩放」。
- **R10 输入框焦点描边。**
  - 做法：让房间码输入框和两个编辑页的文本框获得焦点。
  - 选择：描边出现 → 不改；不出现 → 改为用 bindfocus / bindblur 切换类名。

## Testing Decisions

好的测试只验证外部可观察的行为：纯函数的输入输出、页面数据和用户可见的文案、模板与样式契约、平台 harness 记录到的 wx 调用，以及运行态画面。不断言私有函数的调用次数。优先用现有接缝，新测试遵守 test-seam-guardrail 的接缝约定。

### 1. 纯投影接缝

- **cycle 与 homeCalendarState**：
  - 状态句的全部状态，包括推迟 7 天边界的前后、超出预期的后缀。
  - 两种门槛句、各条含义句。
  - 有进行中经期时当日弹层的动作：覆盖日、未覆盖的更早日、未来日，第一步和第二步各自断言。
  - 图例与色带样本同源。
  - 先例：home-calendar-state、cycle-prediction、calendar-display。
- **periodCoverage**：入口去向表。
  - 被覆盖的日子 → 归属记录。
  - 未覆盖的更早日子 → 第一步给说明，第二步新建已结束。
  - 没有进行中经期 → 按日期新建。
- **calendarInsights**：推迟版说明、经期中超出预期那一句、不出现「置信度」、小结逐条成行，以及复制出的文本。先例：calendar-insights。
- **roomRecordsSync**：
  - 配对三态。
  - 「新到记录」的判定（同一房间码、集合之前已同步、createdByMe 为假、已配对）和清空。
  - 页面隐藏期间先保留。
  - 先例：shared-room-records、home-sync、room-records-snapshot。
- **recordEditRoute 与草稿**：路由日期与草稿日期的匹配规则、「记结束」意图下路由优先、未改动不写草稿。先例：record-edit-route、record-draft。
- **chinaHolidays 与生成脚本**：2027 年条目、发布年上限、脚本对已有年份复现出一致结果。先例：calendar-display。
- **calendarRowHeight**：欢迎条和邀请条共用同一个槽位和账本项；状态行行高不变。先例：narrow-screen-geometry。

### 2. 页面行为接缝（平台 harness）

- **record-edit-page 与 record-flow**：
  - 草稿恢复与放弃、「记结束」意图。
  - 归属询问的三个选项，以及系统返回等于取消。
  - 删除确认带作者，开始日归属的行内提示。
  - 读屏名带值、页面标题、两张卡、作者显示。

- **settings-page 与 settings-flow**：
  - 解绑确认按三种配对状态的文案。
  - 重新同步的面板，以及完成后的 toast。
  - 导出确认和分享失败后的选择。
  - 等待状态下的再发邀请和分享内容。
  - 密度只在变化时写。
  - 使用说明弹层的拖拽与关闭。
- **bind-room-flow 与 room-binding**：
  - 不预选页签、邀请码直达加入、房间码去空白。

  - 页面隐藏时不提交，onShow 无变化时不提交。

- **平台 harness**：增加一条断言，带图标的 toast 标题不超过 7 个字；原生确认键的 4 字上限保留，只约束失败呈现。

### 4. 运行态验收（UI 收尾清单）

- **环境**：模拟器当前机型，替身 Room，构造数据。多机型和小屏按维护者决定不做。
- **覆盖**：
  - **草稿**：在一天新建、改字段、返回，换另一天进入时不恢复；回到同一天时恢复，并能放弃；「记结束」不被盖回。
  - **进行中经期**：上个月的经期日只有记录行；未覆盖的更早日，第一步显示说明块和「记结束」，第二步「补记经期」新建为已结束。
  - **确认面板**：六处都走面板；系统返回、遮罩、下拉、× 都等于取消；危险键清晰可辨。
  - **首页**：状态行各状态；「›」；「图例」按钮；欢迎条可点；含义句；记录行「›」；没有提醒行；两个记录入口分主次；色带两档；骨架换成日历时版面不跳；用箭头翻月和用选月面板跳到同一个月，行高一致。
  - **推迟说明**：文案和「记经期」动作。
  - **配对**：绑定页两个等权入口；邀请码直达加入；「房间建好了」；分享卡片带静态图；设置页和首页再发邀请；创建者的欢迎条；校验期间的说明；解绑后的说明。
  - **记录 tab**：按钮文案、概览卡占位、零记录、重试行形态。
  - **编辑页**：两张卡、结束日期占位、作者、行内归属提示。
  - **一致性**：分段控件三页一致；设置页使用说明可以拖动；房间码样式一致。
  - **最后一个切片**：字号阶梯和透明度档的整体观感，以及几何账本没有越界。
- **判定规则**：R1–R10 的观察和选择写进验证日志。
- **记为未验证**：读屏实听、安卓实机返回键、真机触感，这些模拟器做不了。

## Out of Scope

- **整套引入组件库（TDesign / Vant Weapp / WeUI）。** 项目零运行时依赖，也没开 npm 构建；DESIGN.md 明确不装外部设计系统，2026-11-03 规格也写了不新增 UI 组件库；库的默认视觉是另一套体系，还要多维护一层 token 映射；Vant 与 WeUI 的 npm 版本已停更一年以上。
- **迁 Skyline。** 它的媒体查询只支持 DarkMode，整套减弱动效覆盖会失效；z-index 没有层叠上下文，box-shadow 不能叠加，没有全局滚动；无障碍只支持 role / label / hidden / disabled 四项。
- **用第三方日历组件替换日历网格。** 连续色带、今天胶囊、「预」、两档密度和行高账本都有护栏；候选组件要么是选日期的弹层，要么标记模型不同、最新版还是 alpha。
- **swiper 跟手翻月。** 动效文档登记的是「不跟手」。
- **滚轮式选月。** 一次点选比滚轮快，只修年份步进。
- **一年一年点之外的快速跳年。** 评审只要求修步进。
- **第三方农历库。** 现有查表够用，引库会多 0.5–1 MB 解包体积。
- **库版本的骨架、折叠、列表行、toast、安全区。** 量小，而且各有登记的规则。
- **用库弹层、page-container 或 Skyline 的 draggable-sheet 承载底部弹层。** 库弹层不带跟手下拉、系统返回拦截和弹层交接；page-container 一页只能有一个，缓动不可调；draggable-sheet 只在 Skyline 下可用。
- **自定义 tabBar。** 评审结论是保留原生 tabBar。
- **本轮把弹层和日历做成自定义组件。** 与第 13 节的模板方案互斥，本规格选了模板和共享样式；日历的下发浪费由第 14 节的字段裁剪解决。
- **给原生弹窗登记一个专用深红。** 与「去掉确认色 + 应用内确认面板」互斥。
- **行内重试块降到 60rpx。** 与「统一成整行玫瑰句」互斥。
- **冷启动路线 B。** 与路线 A 互斥。
- **提醒行与状态行同锚点的就地修法。** 与「提醒行并进状态行」互斥。
- **欢迎条写「图例在『工具』里」。** 与「图例」直达互斥。
- **scroll-view 自带的下拉刷新。** 与 R4 选定的做法互斥。
- **完整密度色带保持现状。** 与加边线互斥。
- **失败呈现弹窗迁入应用内面板。** 理由见第 3 节第 3 条。
- **删除后撤销、批量补记、TA 修改或删除记录的痕迹。** 评审只记了现象、没给改法，都需要新的数据模型和产品决定。
- **多机型与兼容性测试。** 按维护者 2026-11-06 的决定不做。
- **算法与云端。** 不改预测算法、周期统计口径、经期三态、云函数、数据库结构和 Room 生命周期。不给任何医疗判断。
