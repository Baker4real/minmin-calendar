# 经期记录年月分组与日历色带位置

**Issue:** [#186](https://github.com/Baker4real/minmin-calendar/issues/186)

**2026-11-12 追加要求：** 用户要求经期记录支持按年收起。当前实现让年份和月份独立折叠、默认全部展开；收起年份保留各月选择，刷新和切换分段保留本页选择，页面重建恢复默认。新增或修改成功同时展开目标年和月。以下原规格中“年份只作标题”与“新增年份折叠不在范围内”保留为 2026-11-11 的原始决策，以本段追加要求为现行行为；其余分组、身份与日期语义不变。

## Problem Statement

用户希望快速按年份和月份找到经期记录，并在日历上一眼分清日期数字与经期标记。当前经期列表是按开始日期倒序的一张长列表，缺少年月层级；粉红经期色带位于日期数字背后，与用户希望的数字下方位置不符。

### 目标与已确认选择

- 经期列表显示“年份标题 → 月份分组 → 经期记录”，时间从新到旧排列，只显示有记录的年月；月份默认全部展开，支持点击收起。
- 经期月份分组按开始日期确定，每条经期唯一归入开始年月；跨月、跨年仍显示同一条完整记录。
- 完整模式的色带移到农历文字背后；清爽模式的色带移到日期数字下方的独立细条位置。两种模式的色带都避开日期数字。
- “今天”的胶囊围住日期数字，即使今天也处于经期，仍与下方经期色带分别表达。

### 已知事实与约束

- 经期记录分为已结束且结束日期已知、进行中、结束日期不详三种状态。只有已知完整起止日期的记录具有精确经期时长；未确认的结束日期保持未知。
- 跨月经期是一个记录实体。列表分组属于展示；本月小结统计的本月覆盖日期不决定列表归组，日历仍显示全部已知覆盖日期。
- 欢乐时光已有按完整年月显示的月份卡和默认展开最近三个有记录月份的行为；本次调整只改变经期分段。
- 现有 Calendar projection 决定经期覆盖、今天、农历及标记含义；日历几何账本决定行高和清爽合并信息行。页面渲染这些结果。
- Aurora Bloom 的色板、字号、对比度、整日触控范围和减弱动效约束继续适用。日期、文字与标记容纳不下时，允许页面自然滚动。

### 关键失效方式

1. 将跨月经期重复列入多个月份，造成重复记录的错觉，或把完整经期时长误写为某个月的覆盖天数。
2. 增加分组后仍用组内下标寻找全局记录，导致点击一行却编辑另一条记录。
3. 保存或删除后仍保留旧分组、空年月或折叠中的目标记录，用户无法找到刚操作的结果。
4. 只移动完整模式的色带，导致清爽、合并信息行或今天处于经期时仍覆盖数字、出现双重描边或丢失今天标记。
5. 色带下移后挤压农历、节日、调休、爱心或“预”，或让相邻日、相邻周的色带连错位置。
6. 机械沿用锁定旧位置的断言，使旧布局继续通过；或只有静态检查，没有真实微信运行态证据。

## Solution

记录页按年份分段，每个年份下面显示有记录的月份，月份下展示经期记录。年份和月份均倒序，月内按开始日期倒序。年份标题用于分隔；月份头明确给出月份与“展开／收起”操作，默认全部展开。

经期月份分组只取记录的开始年月。每一行继续展示原有日期范围、状态、时长、作者、症状、经量与备注。跨月或跨年的一条经期只在开始年月出现，点行继续编辑同一条原记录。

日历的日期数字保持在上方。完整模式把连续粉红色带铺在农历行背后，农历文字绘制在色带上方；清爽模式在数字下方单独显示细色带，并为节日、调休及其他标记保留可读空间。今天的胶囊独立包住日期数字，色带继续只表示经期。

下列均为合成场景：

| 场景 | 列表期望 | 日历期望 |
|---|---|---|
| 2025-03-30 至 2025-04-03 | 仅在2025年3月出现一行，保留完整范围 | 3月和4月分别显示该月实际覆盖日 |
| 2024-12-28 至 2025-01-02 | 仅在2024年12月出现，跨年范围可辨认 | 两年的月视图分别投影覆盖日期 |
| 开始于3月、到4月仍进行中 | 留在3月，继续显示进行中 | 只显示到本次投影采用的今天 |
| 开始日期从3月改到2月 | 同一记录移到2月；3月无记录时移除空组 | 沿用保存后记录重新投影 |

## User Stories

1. 作为查看记录的房间成员，我希望先看到年份，再看到月份，以便快速找到某个时间段的经期。
2. 作为查看记录的房间成员，我希望年份、月份和月内记录都从新到旧排列，以便优先查看近期记录。
3. 作为查看记录的房间成员，我希望只显示有经期记录的年月，以便减少空分组干扰。
4. 作为查看记录的房间成员，我希望月份默认全部展开，以便打开记录页就能看到具体记录。
5. 作为查看记录的房间成员，我希望点击月份头就能展开或收起，以便减少暂时不需要查看的内容。
6. 作为查看记录的房间成员，我希望展开收起只影响目标月份，以便其他月份的阅读位置保持清楚。
7. 作为查看记录的房间成员，我希望切换分段或刷新后保留本次页面中的手动折叠选择，以便无需重复操作。
8. 作为补记经期的房间成员，我希望同一月的多条记录都能保留，以便分组不会合并或丢弃真实记录。
9. 作为查看跨月经期的房间成员，我希望它只归入开始月份，以便把一段连续经期理解为一条记录。
10. 作为查看跨年经期的房间成员，我希望它归入开始年份，并保留可辨认的跨年范围，以便明确记录发生的完整时段。
11. 作为查看进行中经期的房间成员，我希望经过月末后记录仍留在开始月份，以便记录归属稳定。
12. 作为查看结束日期不详记录的房间成员，我希望保留该状态，以便界面不会暗示一个未经确认的结束日或时长。
13. 作为查看记录的房间成员，我希望原有作者、症状、经量、备注和时长信息继续显示，以便分组后仍能了解记录详情。
14. 作为编辑经期的房间成员，我希望点击任一月份里的行都打开对应的原记录，以便修改不会落到其他记录上。
15. 作为编辑经期的房间成员，我希望修改开始年月后记录移动到新分组，并展开目标月份，以便能看到保存结果。
16. 作为删除记录的房间成员，我希望删除该月或该年的最后一条记录后移除空分组，以便列表与实际记录一致。
17. 作为查看记录的房间成员，我希望加载失败时仍能识别失败并重试，以便不会把请求失败误认为没有经期。
18. 作为查看记录的房间成员，我希望刷新失败时保留上次已显示的列表及折叠状态，以便已有内容仍可查看。
19. 作为查看欢乐时光的房间成员，我希望其现有月份卡和默认展开行为保持不变，以便这次经期调整不会改变另一分段的用法。
20. 作为使用完整日历模式的房间成员，我希望粉红色带位于农历文字背后，以便日期数字清晰露出。
21. 作为使用清爽日历模式的房间成员，我希望经期以数字下方的独立细条显示，以便没有农历时仍能辨认经期。
22. 作为使用短屏日历的房间成员，我希望合并信息行时仍看得见数字、色带和其他标记，以便节省空间不会丢失含义。
23. 作为查看今天的房间成员，我希望日期数字保留今天胶囊，以便无论是否处于经期都能找到今天。
24. 作为查看连续经期的房间成员，我希望色带在同一周连续、起止处有圆头，以便辨认实际覆盖范围。
25. 作为查看跨周经期的房间成员，我希望色带在周边界正确分段，以便不会与相邻周的日期混淆。
26. 作为查看单日或进行中经期的房间成员，我希望单日圆头和进行中末端开口继续表达原有含义，以便不会误读结束状态。
27. 作为查看节日、调休或欢乐时光的房间成员，我希望对应文字和爱心不被色带遮住，以便同一天的不同信息都可辨认。
28. 作为查看预测的房间成员，我希望“预”继续表示可能开始的日子，重叠日抑制“预”并保留经期和已有欢乐时光，以便预测与实录含义不混淆。
29. 作为使用读屏的房间成员，我希望月份头读出完整年月和展开状态、记录行继续读出完整含义，以便能够导航和编辑。
30. 作为使用较窄屏幕的房间成员，我希望年月标题、日期范围和操作不横向溢出，以便不缩小文字也能阅读和点击。
31. 作为开启减弱动效的房间成员，我希望展开收起即时完成、原有反馈遵循减弱动效规则，以便操作结果清楚且稳定。
32. 作为保存经期记录的房间成员，我希望返回首页时原有成功反馈仍发生在正确覆盖日期，以便色带换位置后反馈仍可信。
33. 作为共享私密日历的房间成员，我希望公开规格和验收证据只使用合成记录，以便真实经期、备注和房间信息不会被公开。

## Implementation Decisions

1. **分组是展示投影。** 经期月份分组根据完整开始年月形成，再按年份组织展示。年份、月份和组内开始日期均倒序；相同开始日期保留原有相对顺序。每条记录出现一次，保留原始身份及现有装饰字段。
2. **状态与归组分开。** 进行中、结束日期不详、已知结束共用开始年月归类规则；沿用现有排序，不另设进行中置顶。日历覆盖、归属记录、经期时长和本月小结的覆盖并集继续由现有领域机制负责。
3. **折叠由记录页持有。** 年份只作标题，月份头提供“展开／收起”；首次进入默认全部展开。手动选择仅在页面内存按完整年月保存，刷新和切换分段保留，页面重新创建时回到默认。点击月份头不导航，收起时不渲染该月记录行，沿用现有即时切换和读屏状态表达。
4. **按记录身份编辑。** 分组内点击必须定位原记录，避免组内下标与全局下标混用。新增或修改成功后展开保存结果所在月份；开始年月改变时归入目标月。删除后移除空月份和空年份；保存失败或取消编辑保持原展示。
5. **沿用现有页面状态。** 首次加载、无记录、首次失败、已有数据后刷新失败沿用原有反馈。列表刷新成功后统一更新分组与记录；失败不清空已显示的分组和手动折叠选择。分组不增加远程请求或本地持久化。
6. **沿用既有写入与同步边界。** RoomDataClient 继续作为前端记录读写入口；编辑会话继续负责保存、草稿和通知；首页记录同步继续负责采纳快照。本次不把这些职责移回页面，遵守 ADR-0005、ADR-0007 和 ADR-0008。
7. **色带使用相应内容槽位。** 完整模式以农历行定位色带；清爽模式在日期数字下方保留独立细条位置。完整、清爽常规排版和清爽合并信息行都满足数字与色带分离；格内几何继续通过既有账本统一计算，不用缩字或裁字解决空间不足。
8. **今天与经期分别表达。** 所有今天格子都在日期数字处显示今天胶囊；经期今天也使用该胶囊，去掉下方色带对今天的专属描边。今天的回到今天强调仍定位日期胶囊，避免遗留双描边或数字对比度不足。
9. **保留色带形态与语义。** 沿用经期玫瑰色、同周连续、单日及起止圆头、跨周分段和进行中末端开口。农历及其他文字在色带之上保持可读。重叠日继续抑制“预”，保留经期和当天已有的欢乐时光；保存成功的反馈仍沿用原有触发与减弱动效规则。
10. **共享样本保持一致。** 图例、记经期入口和经期动作继续复用同一经期色带样本。修改网格位置时为样本保留其语义化尺寸与居中呈现，今天图例与经期今天的实际新表现一致。
11. **视觉文档随实现同步。** 本规格明确替代原有“经期色带包住数字”和“经期今天由色带描边表达”的规则。实现时同步现行视觉与动效交互说明及受影响的静态守卫；其余 Aurora Bloom 规则沿用。本次是可逆展示调整，无需新增 ADR、数据迁移、远程契约或运行时依赖。

## Testing Decisions

### 主测试边界与既有先例

- 行为优先通过现有小程序平台 harness，驱动真实页面生命周期与用户事件，控制云请求应答和时间，观察页面渲染数据、导航、提示及存储。记录 tab 现有测试已覆盖跨月单条经期、三态、欢乐时光月份展开保留及保存回流，可直接扩展这些先例。
- 首页继续使用既有 Calendar projection 与页面事件边界，核对经期覆盖、今天、其他标记和保存反馈。不为了分组另建内部测试接口，不 mock 应用模块，不通过 JavaScript 源码字符串锁定私有方法或存储结构。
- 布局复用现有日历微字、窄屏几何、对比度、交互语义和动效守卫。检查可观察的槽位关系、可读性和命中范围；旧位置断言须随本规格替换为新布局关系，保留针对真正错误的失败能力。
- 静态几何无法证明微信实际排版，须补充模拟器当前机型的实际渲染和编辑回流证据。测试边界沿用既有体系，不新增通用测试框架。

### 行为验收

- [ ] 多年、缺月、同月多条输入形成正确的年份与月份倒序；每个记录身份恰好出现一次，同开始日期保持原有相对顺序。
- [ ] 跨月、跨年、进行中和结束日期不详均只归开始年月；保留完整范围、原有状态与时长表达，不补写结束日。
- [ ] 月份默认全部展开，点击仅切换目标月，切换分段或刷新后保留本次页面手动选择；重建页面恢复默认，选择不落本地存储。
- [ ] 在不同年份和月份中点击记录均编辑正确身份；保存后移动到目标年月并展开目标月，删除最后一条后移除空月与空年。
- [ ] 首次失败、刷新失败、重试、成功返回空集合都沿用正确反馈；失败不把旧数据清空或显示成首次无记录。
- [ ] 欢乐时光现有年月排序、默认展开窗口、编辑与作者呈现保持通过；经期统计、日历覆盖和本月小结计数不因列表分组变化。

### 布局与交互验收

- [ ] 完整模式中，色带位于农历行，日期数字与今天胶囊在其上方；农历字符完整可读。
- [ ] 清爽模式及清爽合并信息行中，细色带独立位于数字下方，不覆盖日期、今天胶囊、节日、调休、爱心或“预”。
- [ ] 单日、同周连续、跨周、月边界及进行中末端的色带连接和圆头正确，空格不画色带，相邻周不串连。
- [ ] 经期今天只在数字位置显示今天胶囊，下方色带不遗留今天描边；非经期今天的表现保持一致。
- [ ] 日历图例、记经期入口、经期动作、回到今天强调及保存成功反馈均与受影响的新表现一致。
- [ ] 现有320、375、430宽度的自动几何与坐标回归通过；较长跨年日期、月份头、症状与备注不造成横向溢出或遮挡。
- [ ] 在微信模拟器当前机型回读实际视口，分别查看完整、清爽模式及相关叠加状态，并走完折叠、编辑、保存后回流流程。遵循维护者现有决定，不为本任务切换机型；小屏运行态标为“按维护者决定不做”。
- [ ] 月份头有可读的完整年月、展开状态和操作名；整日点击范围及原有记录行读屏含义保留，减弱动效下仍可操作。

### 完成标准

实现者运行项目 README Verification 规定的完整轻量组合与 `git diff --check`，按 UI 收尾清单报告实际视口、密度、关键流程及证据位置。静态检查通过不代替微信验收；缺失的运行态证据明确列为未验证，不将“文件已修改”称为功能完成。若后续按 epic 收口，按项目规则追加当日验证记录。

## Out of Scope

- 改变经期或欢乐时光的数据结构、云函数、Room 生命周期、授权、导出格式或记录写入协议。
- 按月拆分或复制经期记录、补写未知结束日期、改变预测算法、归属记录或经期覆盖统计。
- 调整欢乐时光的分组层级或默认展开窗口，新增年份折叠、年月筛选、搜索、跳转、分页或折叠状态跨重启持久化。
- 改变整套主题、字号角色、增加独立动画或通用状态管理、重构与此功能无关的模块。
