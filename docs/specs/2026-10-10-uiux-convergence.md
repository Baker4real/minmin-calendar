# UI/UX 全面收敛：经期做主角、TA 看得见、默认值不再写坏数据

**Date:** 2026-10-10
**Status:** Accepted
**Issue:** #123（私有 GitHub tracker 上的 epic 父票，正文与本文件同源）

## Problem Statement

两个人用这个小程序，真正想要的是三件事：扫一眼就知道「上次从哪天到哪天、这次是第几天、下次大概哪天」；记录经期时不用动脑、也不会记错；能感觉到这是两个人共用的日历。现在这三件事都打了折扣，外壳和细节还在每个页面上反复磕碰。

**1. 日历的主角放错了**

- 经期只是每个日期格底部约 4px 的玫瑰小点。节日是金色实底胶囊，外加整格金底；每格还有四个字的农历。结果节日和农历比用户自己的经期更显眼，一整段经期在月视图里几乎看不出来。
- 进行中的经期和已结束的经期在日历上长得一样，只有读屏名里能区分。
- 图例画的符号和日历格里的不是同一个样子：
  - 经期：图例是实心圆盘，格里是小点；
  - 「班」：图例是金底，格里是灰底；
  - 「预」：图例是实底，格里是描边。
- 图例说"今天"用玫瑰色光圈，实际是薰衣草描边。
- 「预」的语义含混：
  - 实际表示"下次可能开始的日子"，即预计开始日前后几天；
  - 图例却叫它"下次经期的预测区间"；
  - 首页"预测下次"的日期又不是这个窗口的第一天，两者是什么关系，界面上没有解释。
- 其他措辞与配色：
  - "置信度：高"不是日常说法；
  - 经期推迟时用的是警示红，会放大焦虑。
- 首页没有用户最常看的信息：既没有"经期第几天"，也没有"还有几天"。状态卡最好的位置给了累计条数"经期记录 N"，它是玫瑰色，却不能点。
- 按 390×844 推算，6 行的月份会把预测卡挤出首屏。

**2. 维护经期最常见的几步，默认值会把数据存错**

- 结束一次进行中的经期时，把状态切到「已结束」，结束日默认等于开始日。匆忙保存，就是一条只有 1 天的经期，平均时长和预测都会被拉偏。
- 补记过去某一天的经期，默认也是"已结束、起止同一天"。
- 首页「记经期」不随状态变化。已经有进行中的经期时，首页会静默打开旧记录；记录页做同一个动作，却会先提示一句。
- 在日历上点开一个经期日，问题有三个：
  - 详情里的记录不能点开编辑；
  - 唯一的动作「补经期」会以当天为开始日新建一条，和原记录重叠；
  - 保存后日历外观不变，用户容易以为没成功，再点一次。
- 经期超期未结束的提醒，一渲染就被记为"已提醒"。用户没看到，它也不会再出现。
- 保存结果未确认时，界面让用户"返回列表刷新后检查是否已生效"，把核对工作交给了用户。
- 同一条"结束日期不详"的记录，这几个字会在同一行显示两遍。
- 未来的日子在当日弹层里仍可以选「欢乐时光」。编辑页会带着这个未来日期打开，客户端和云端都不拦截，保存后爱心就出现在未来，违反了"记录日期不能在未来"。

**3. "两个人"在绑定后几乎看不见，第二个人的第一步还是坏的**

- 加入房间时，房间码输入框里的字被裁掉一半，而且偏左。首屏副标题的换行不生效，两句话粘在一起。这两点都是开发者工具实拍，用的是模拟的未绑定视图态。
- 只能复制 6 位房间码再手动发给对方，没有微信分享卡。
- 双方互相看不见：
  - 创建者不知道 TA 什么时候加入；
  - 设置页看不到房间里还有谁；
  - 记录分不清是谁记的；
  - 对方刚记的内容要等下次切回页面才出现，没有下拉刷新。
- 房间状态变化缺少反馈：
  - 归档房间通过「创建」恢复后，界面不会说"已恢复原来的房间和记录"；
  - 解绑成功后没有任何确认；
  - 解绑确认文案是从绑定页照搬到设置页的，"可在本页重新创建恢复"指错了页，也没说 TA 那边会怎样。
- 网络失败时，界面会出现"云数据库查询超时 (15000ms)"，或"加入失败：""同步房间状态失败："后面直接拼原始错误这类技术字符串。

**4. 外壳与细节在每个页面上反复磕碰**

- **导航栏不固定**：自定义导航栏随内容一起滚走。一滚动，内容就钻到状态栏和微信胶囊下面；胶囊会压住首页的「›」「…」、记录页的分段和新增按钮、编辑页的返回键，还会吃掉点按。
- **当日弹层**：
  - 要多点一步才能看到当天内容，详情还先复述一遍图例；
  - 预测说明和小结是"一句话一个盒子"，看起来像可点的按钮；
  - 小结内容重复，弹层标题用的是 ISO 日期；
  - 弹层打开时，底部 tab 仍然能点；安卓返回键会直接离开页面，而不是先关弹层。
- **月份导航**：「…」夹在月份标题和「›」之间，大小样式和翻月按钮一样，容易误触；首页没有"回到今天"；选月要先选、再点"跳转到…"；不能左右滑动翻月。
- **写法不统一**：
  - 日期有三种写法：ISO、"0M月0D日"、"M月D日"；
  - 同一个东西有四个名字：欢乐时光、记忆、特别日子、特别时刻；同一个动作有五种说法；
  - 分段控件有两种选中态，主按钮有两种形状。
- **设置页**：
  - 一行一张卡，装饰性的 hero 卡占了首屏约五分之一；
  - "解除绑定"紧贴在房间码和复制按钮下面；
  - "清除本地数据"其实只是重新同步房间码，却用了警示红；
  - "欢乐时光"入口和记录 tab 重复；
  - "清爽"模式的说明和实际显示不符；
  - 全应用没有任何使用说明。
- **欢乐时光回顾**：默认只展开最近一个月，回顾时要逐月点开；旧的欢乐时光页面还是第三种列表样式。
- **编辑页**：备注夹在状态和经量之间；"睡眠差""嘴馋"被归到"情绪"下；删除键紧贴保存键，确认按钮只写"确定"；占位提示只有 0.35 白，看不清。
- **对比度**：三处组合状态的文字不达 WCAG AA：
  - 进行中经期的时长胶囊约 3.58:1；
  - 今天落在预测窗口时的「预」约 3.95:1；
  - 嵌在状态卡里的提醒说明约 4.1:1。
- **渲染开销**：
  - 首页静置时，5 个带 backdrop-filter 的面叠在持续动画的极光背景上，每帧都要重算模糊；而这些面的合成不透明度约 92.6%，模糊几乎看不见；
  - 不可点的元素也在发光；
  - 按压底色写在 background-image 层，标称 160ms 的过渡实际是瞬间切换；
  - 首页把渲染用不到的数据（逐日详情映射、含备注的完整记录数组）也传给了渲染层。
- **测试与验证**：main 上的护栏测试有 2 项失败（676 项中 674 通过），是把 hover-class 并进 `:active` 选择器组的那次提交引入的，README 里"全绿"的说法已经过时。首启页从 Aurora 收敛以来一直没有在开发者工具里目检过。

**来源**：2026-10-09，用户用 impeccable（pbakaus/impeccable）对本项目做了全面 UI/UX 评审：
- critique 设计健康分 24/40，audit 技术审计 12/20；
- 证据包括：开发者工具模拟器实拍 33 张（390×844）、两个隔离的评审子代理、检测器 HTML shim 扫描（42 条，确认 32 条）、全量测试。

本 spec 按用户要求，把发现的全部问题和推荐修改项整合在一起。

## Solution

- **经期是日历的主角**：
  - 经期画成一条横跨日期的连续玫瑰色带：起止两端圆头，进行中的末端开口；跨周时在行首、行尾自然收口；单日经期是一个圆块。
  - 节日退为无底金字，去掉整格金底；农历只写日，初一写月名。
  - 图例和格内标记用同一套样式渲染，长得一模一样。
- **最常看的信息永远在首屏**：月份导航下方加一行状态，和月份导航一起吸顶。内容随情况变化：
  - 经期中：经期第 N 天；
  - 经期前：预计 X月X日 开始 · 还有 N 天；
  - 进入可能开始的那几天：这几天可能开始；
  - 推迟：比预计晚 N 天；
  - 记录不够：暂时无法预测。

  「预」统一叫"可能开始的日子"；预测说明第一句就写开始日和"前后 N 天都正常"；推迟不再用警示红。
- **"记经期"懂状态，默认值不再写坏数据**：
  - 有进行中的经期时，按钮变成「经期第 N 天 · 记结束」。点开就是那条记录，已预选「已结束」，结束日是今天，下面实时显示"共 N 天"。
  - 补记过去的经期，结束日要自己选，不再悄悄等于开始日。
  - 点在已有经期上的日子，永远打开那条记录，不会新建重叠记录。
- **点一天就看到那天**：
  - 有记录的日子直接显示详情，每条记录都能点进编辑；
  - 没记录的日子显示可以做的动作；
  - 标题写成"10月9日 周五"；
  - 不再复述图例。
- **两个人看得见彼此**：
  - 创建房间后一键「发给 TA」，TA 点开邀请卡，加入页已经填好房间码；
  - TA 加入后，创建者会看到一次"TA 已加入"；设置页显示成员状态；
  - 每条记录标明"我记的 / TA 记的"；
  - 首页和记录页可以下拉刷新；
  - 恢复房间、解绑成功都有明确的反馈。
- **外壳稳**：
  - 所有页面共享一个固定顶栏，按微信胶囊的位置计算高度并让出胶囊宽度，内容永远不会钻到状态栏和胶囊下面；
  - 系统返回先关弹层；弹层期间底部 tab 不会被误触；
  - 首页可以左右滑动翻月，选月点一下即跳转，不在当月时出现"回到今天"。
- **说人话，只有一种写法**：
  - 日期只有一种显示格式；同一个东西一个名字，同一个动作一种说法；
  - 错误都是人话，并附带重试；
  - 破坏性按钮直接写明动作（"删除""解除绑定"），用警示色；
  - 空态告诉用户下一步做什么。
- **设置页清楚**：分为房间、日历显示、数据、关于四组，危险操作集中在页底。"清除本地数据"改叫"重新同步房间"，不再用警示红。"关于"里有使用说明。
- **看得清、跑得轻**：
  - 组合状态的对比度达标，并纳入护栏；
  - 近乎不透明的面去掉看不见的模糊，极光层缩小；
  - 只有主按钮和复制键保留辉光；
  - 按压反馈处处一致，而且真的有过渡；
  - 渲染层只接收模板需要的数据。
- **先让护栏转绿**；DESIGN.md、ADR 0007、CONTEXT.md 与新行为保持一致。

除"记录作者"需要部署 dataOp 云函数外，其余全部是前端改动，不改房间生命周期云函数，也不改数据结构。减弱动效下，所有新增交互都有即时版本。

## User Stories

经期记录的生命周期：

1. 作为记录经期的人，有进行中的经期时，我想首页按钮直接写「经期第 N 天 · 记结束」，这样结束一次经期只需要点一下再确认。
2. 作为结束经期的人，我想点「记结束」打开的就是那条进行中记录，状态已经预选「已结束」，结束日是今天，这样默认值就是最可能的事实。
3. 作为结束经期的人，我想表单在结束日下方实时显示"共 N 天"，这样保存前能确认时长对不对。
4. 作为拖了几天才来补结束日的人，如果算出来的天数明显长于我以往的经期，我想看到一句"比你通常的 N 天长，确认一下结束日？"，这样不会把结束日记错；这句提示不改我的任何选择。
5. 作为补记过去经期的人，我想表单不再悄悄把结束日填成开始日，而是请我自己选结束日，这样不会存出一条"只有 1 天"的经期。
6. 作为补记过去经期、其实还没结束的人，我想提示告诉我"还没结束可以选「进行中」"。
7. 作为补记但记不清结束日的人，我想仍然可以选「结束日期不详」直接保存。
8. 作为在编辑页把一条新记录切到「已结束」的人，我想结束日留空等我自己选，而不是自动等于开始日。
9. 作为没选结束日就点保存的人，我想看到"请选择结束日期；还没结束可以选「进行中」"，而不是笼统的"请选择有效日期"。
10. 作为在首页点「记经期」、而房间里已有进行中经期的人，我想先看到"已有进行中的经期，继续编辑它"，和记录页的说法一致。
11. 作为在日历某天点「记经期」的人，如果这天已经落在某段经期里，我想直接打开那段经期，而不是新建一条重叠的记录。
12. 作为新建经期的人，如果开始日落在已有经期的范围内，我想保存前收到提醒，并可以选择改去编辑那一条，这样不会无意中记重复。
13. 作为确实要分开记两段的人，我想在那个提醒里仍能选择"仍然新建"，因为重叠记录不被硬性禁止。
14. 作为看经期列表的人，我想"结束日期不详"在一行里只出现一次。
15. 作为看日历的人，我想进行中的经期和已结束的经期看得出区别（进行中的色带末端开口），这样一眼就知道"还在进行"。
16. 作为经期超期还没结束的人，我想提醒要等我真正看到之后才算"已提醒"：点过它，或者它显示期间我离开了首页。这样它不会一闪而过就再也看不到。
17. 作为保存时网络结果没回来的人，我想 App 自己重新拉取核对，然后明确告诉我"已保存"或"没有保存成功，请重试"，而不是让我自己去列表里找。

日历标记与图例：

18. 作为扫一眼日历的人，我想经期是一条连续的玫瑰色带，起止两端圆头，这样"上次从哪天到哪天"一眼可见。
19. 作为看跨周经期的人，我想色带在行尾和下一行行首自然收口，而不是断成看不懂的碎片。
20. 作为只记了一天经期的人，我想那天显示成一个圆块，和连续色带区分开。
21. 作为今天正在经期里的人，我想今天的薰衣草描边仍然清楚可见，不被色带盖住。
22. 作为在经期日也留了欢乐时光的人，我想 ♥ 在色带上依然清楚。
23. 作为看日历的人，我想节日是无底的金色文字，没有整格金底，这样节日是背景信息，不抢经期的风头。
24. 作为看日历的人，我想调休「班」保持低调的小标签。
25. 作为用完整密度的人，我想农历只显示日（例如"廿九"），每月初一显示月名，这样格子不再挤满四个字。
26. 作为用清爽密度的人，我想设置页如实写明：清爽模式只看日期与标记（含节日和调休），完整模式另外显示农历。
27. 作为对照图例的人，我想图例里每个符号和日历格里的完全一样，这样我能照着对上。
28. 作为看图例的人，我想"今天"的说明和它实际的样子一致。
29. 作为看当日详情的人，我想经期记录的标签用玫瑰色、欢乐时光用浅粉色，金色只用来表示预测和节日。
30. 作为今天正好落在预测窗口里的人，我想格内的「预」仍然清楚可读。
31. 作为看日历的人，我想网格最左和最右两列的内容不贴着边框。
32. 作为开启减弱动效的人，我想色带和标记直接出现，没有任何动画。
33. 作为读屏用户，我想日历格朗读出完整含义，例如"经期第 N 天""经期进行中""可能开始的日子""节日名"，并且和新的视觉表达一致。

预测与首页状态：

34. 作为看首页的人，我想月份导航下方有一行状态：经期中显示"经期第 N 天"，经期前显示"预计 X月X日 开始 · 还有 N 天"，这样最常看的信息永远在首屏。
35. 作为进入可能开始那几天的人，我想状态行写"这几天可能开始"，而不是一个已经过去的倒数。
36. 作为经期推迟的人，我想状态行写"比预计晚 N 天"，并用中性色，不用警示红。
37. 作为记录还不够的人，我想状态行说明"多记几次后就能预测"，而不是一片空白或"--"。
38. 作为想知道预测怎么来的人，我想点状态行就打开预测说明。
39. 作为看图例和预测说明的人，我想「预」的意思统一是"下次可能开始的日子"，不再叫"预测区间"。
40. 作为看预测说明的人，我想第一句就是"预计 X月X日 开始，前后 N 天都正常"，再说依据（参考了几次周期、平均周期和平均持续天数）。
41. 作为看预测说明的人，我想"置信度：高/中/低"换成口语，比如"最近几次很规律，比较准"或"记录还不多，仅供参考"。

## Implementation Decisions

约束与已定原则（不在本 spec 里改）：

- **CONTEXT.md 的产品原则不变**：
  - 一个视觉符号只表达一个含义；重叠日只表达经期；
  - 记录日期不能在未来；
  - 系统不猜结束日，也不自动关闭进行中的经期；
  - 预测是轻量估算，不是医疗建议；
  - 共享数据只在房间内可见。
- **ADR 0007 的核心不变**：
  - 三态经期；
  - 不用开始日充当进行中经期的临时结束日；
  - 不按典型长度自动写入结束日；
  - 同一 Room 只有一条进行中经期，由云端写入路径兜底。
- **DESIGN.md 仍是唯一视觉权威，系统名仍是 Aurora Bloom**：
  - 暗色唯一主题，系统字体；
  - 玫瑰是唯一明亮的可点色，金色只表示预测和日历元数据；
  - 触控目标至少 44px；deny-by-default 护栏；现行减弱动效政策。
- **云函数范围**：房间生命周期四个云函数（create、join、getMyRoom、leave）不改。

前置：

- **先让护栏测试转绿**：
  - 设计 token 护栏的白名单解析和绑定页流程测试的规则查找，都要能识别"`:active` 与 hover-class 并列的选择器组"；
  - 规则本身不放宽：渐变 / 实色玫瑰填充仍是 deny-by-default；
  - 这一步先单独完成，后续切片都依赖它。

经期生命周期（ADR 0007 追加第三条补充，并撤回 2026-10-08 补充里"补记过去时结束日兜底为开始日"的那半句）：

- **完成一条进行中的记录**：状态切到「已结束」时，结束日默认是今天。表单实时显示含首尾的天数。如果天数超过预期时长，只显示一句核对提示，不改任何选择。
  - 判断口径与超期完成提醒一致，预期时长的来源优先级也相同：用户设置 → 已完成记录的中位数 → 五天默认。
- **新增且开始日早于今天**：状态默认仍是「已结束」，但结束日留空、必须由用户自己选。保存校验的文案改为"请选择结束日期；还没结束可以选「进行中」"。
- **其他情况切到「已结束」且结束日为空**：保持为空，等用户选择，不再兜底为开始日。
- **"为某一天记经期"只有一条决策**，首页 CTA、日历当日弹层、周期提醒共用。按顺序判断：
  1. 有进行中的记录 → 打开它，并给出与记录页相同的提示；
  2. 这一天落在某条已有记录的投影范围内 → 打开那条；
  3. 否则以这一天为开始日新建。
- **页面层重叠检查**：保存一条新记录时，如果开始日落在已有记录的投影范围内，弹出确认，选项为"去编辑那条 / 仍然新建"。云端不加硬性拦截，符合 CONTEXT.md"重叠记录另行处理"的约定。
- **超期完成提醒**：不在渲染时持久化"已提醒"。只有用户点按了提醒，或者首页在显示过它之后被离开时，才记为已提醒。
- **保存结果未确认**：页面自动重新拉取一次该集合，然后确认结果：编辑按记录身份核对，新增按日期和内容核对。确认后给出"已保存"或"没有保存成功，请重试"。只有重新拉取也失败时，才回退到现在的说明。
- **未来日期**：
  - 当日弹层在未来的日子不提供任何记录动作；
  - 欢乐时光编辑页校验"日期不能晚于今天"，路由带进来的未来日期会被拦下并提示；
  - dataOp 对欢乐时光的日期同样拒绝未来日期，与经期一致，并和"记录作者"一起部署。
- **"结束日期不详"去重**：列表行里，这几个字只出现在一个位置。

日历投影（homeCalendarState，纯函数）：

- **经期段位**：每个日期格输出段位，取值为 无 / 起点 / 中段 / 终点 / 单日，外加"开放端"标记（进行中经期投影到今天的那一端）。
  - 按周换行时，行首和行尾按起点、终点收口。
  - 重叠日仍然只表达经期。
- **图例**：图例项输出与格内标记相同的标记描述，模板复用格内的同一套样式类。"今天"的说明改成实际外观：薰衣草描边、玫瑰底、玫瑰色日期。
- **农历**：完整密度下，格内只显示日名，初一显示月名；完整的农历字符串保留在读屏名和详情副标题里。清爽密度的行为不变，设置页说明同步修正。
- **当日详情**：
  - 去掉"今天 / 经期 / 欢乐时光"三类说明卡，保留预测、节日、调休的说明句；
  - 每条记录行带上编辑目标（记录身份）；
  - 标签颜色按记录类型：经期玫瑰，欢乐时光浅粉；金色只留给预测和节日。
- **读屏名**：随新表达更新，例如"经期第 N 天""经期进行中""可能开始的日子"。语义文案仍然只从本模块产出。

预测呈现（cycle、calendarInsights）：

- **算法不变**：预计开始日 = 上次开始日 + 平均周期；窗口 = 预计开始日 ± 波动天数。
- **术语**：「预」= "下次可能开始的日子"。图例、详情、说明统一使用这个说法。
- **首页状态行**由一个纯函数给出状态和文案，状态取值：
  - 经期中：第 N 天；
  - 预计前：还有 N 天；
  - 窗口内：这几天可能开始；
  - 推迟：比预计晚 N 天；
  - 数据不足。

  状态行点按后打开预测说明。
- **预测说明**：首句为"预计 X月X日 开始，前后 N 天都正常"；随后是依据和预计持续天数；结尾加一句"根据记录估算，不是医疗建议"。置信度改成口语映射。
- **推迟提醒**：从警示红族移出，改用中性色，配安抚文案。警示红族在 DESIGN.md 里去掉"逾期提醒"这一形态。
- **本月小结**：
  - 去掉重复项："N 条欢乐时光"与"N 个特别日子"；"跨月延续"与"经期区间"；
  - 标题与副标题去重；"（高）"带上标签；
  - 日期改走统一格式；
  - 复制文本同步修改。

日期显示的单一出口（util）：

- 提供唯一一组显示格式：
  - "M月D日"；
  - "M月D日 周X"；
  - 年份不是当年时带年份；
  - 区间用"M月D日–M月D日"。

- 全应用（列表、详情、弹层标题、小结、预测、表单回显）都改走这个出口。零填充的中文格式退役。

  2. 吸顶区：月份导航「‹ 年月 ⌄ ›」，不在当月时加"回到今天"，下面是状态行；
  3. 周头与日历；
  4. 记录入口：「记经期」会随状态变成「经期第 N 天 · 记结束」，旁边是「记欢乐时光」；
  5. 本月小结行与提醒行，提醒不再嵌在卡片里；
  6. 空态引导。
- **工具入口**：移到顶栏左侧空位，仍是现有菜单：图例、预测说明、本月小结。小结在首页另有直达行。累计条数"经期记录 N"从首页移除。
- **日历行高**：在"触控下限 44px"到"现有上限"之间，按可用高度计算。保证 390×844 下各密度、375×667 下清爽密度的 6 行月份里，记录入口仍在首屏。状态行在任何情况下都可见（吸顶）。
- **首次加载**：用日历骨架代替转圈，骨架复用记录页的静态 / 脉冲规则和减弱动效替代。

共享顶栏与外壳：

- **一个共享顶栏**，7 个页面统一使用：
  - 高度 = 状态栏高度 + 由微信胶囊矩形推出的导航高度；
  - 右侧预留胶囊宽度；
  - 固定定位，页面内容区同步下移；
  - 编辑页的返回键常驻在顶栏内。
- safeArea 模块新增胶囊矩形的计算，与现有顶部、底部注入共用同一个运行时出口。
- **月份导航与状态行吸顶**：位于顶栏下方。如果目标基础库对 sticky 的支持不可靠，改为在顶栏下固定，并给内容区留出占位。
- **左右滑动翻月**：
  - 在日历区域用 WXS 处理，与弹层拖动是同一种模式；
  - 水平位移超过阈值、且大于竖直位移时才触发，否则交给轻点和页面滚动；
  - 不跟手、不加翻页动画，松手即翻月，和现有"一次页面更新完成翻月"的约定一致；
  - 减弱动效下同样即时。
- **选月即跳**：在选月弹层里点月份格，直接跳转并关闭弹层；年份步进和"回到今天"保留，确认按钮退役。
- **弹层结构与系统返回**：
  - 遮罩和面板改为兄弟节点，遮罩单独作为"关闭"控件朗读，面板内的控件各自可达；
  - 弹层打开期间拦截系统返回（可借助小程序的页面离开拦截能力），先走现有的离场生命周期；
  - 原生 tabBar 在弹层打开时隐藏，离场完成后恢复，减弱动效下即时；
  - 现有的弹层生命周期、拖动关闭、交接、暂停装饰等行为都不变。
- **下拉刷新**：首页与记录 tab 开启，触发现有的后台刷新路径，完成或失败后停止，失败提示沿用现有的"刷新失败"文案。

TA 的首启与双人感：

- **绑定页修正**：
  - 房间码输入框设置显式高度和行高（不小于 88rpx 触控档，文字完整可见），居中或通栏，与上方说明、下方主按钮对齐；
  - 副标题的换行改用文本内换行符；
  - 新增静态护栏：`text` 内不得出现 `br` 标签。
- **分享邀请**：
  - 创建成功后，在"把房间码发给 TA"处提供分享按钮（小程序原生分享）；
  - 分享路径指向启动首屏，携带房间码参数；
  - 分享卡标题使用固定文案，不含任何经期或记录信息；
  - 绑定页加载时读取该参数：如果未绑定，切到"加入房间"并预填，仍需用户点"加入"；如果已绑定，忽略该参数，按现有逻辑进首页。
- **加入成功**：首页显示一次性的欢迎条，内容为"已和 TA 连上"和一句标记说明，用本地存储去重。
- **房间状态透出**：getMyRoom 已经返回房间文档（含 waiting / paired 状态）。room 会话模块把这个状态透出给页面，不改云函数。
  - 创建者在状态由 waiting 变为 paired 后第一次进入首页或设置页时，看到一次"TA 已加入"（本地记录上次看到的状态）；
  - 设置页房间组显示成员状态。
- **归档恢复提示**：创建成功后，如果第一次拉取的记录非空，就提示"已恢复原来的房间和 N 条记录"。这是客户端推断，不改 createRoom。
- **解绑**：
  - 成功后用一次性意图键，让绑定页提示"已解除绑定"；
  - 确认文案改成：说明自己会退出、TA 会留在房间里（或房间只剩自己时会被归档）、在绑定页点"创建"即可恢复；
  - 确认按钮写"解除绑定"，并用警示色。

记录作者（唯一的云端改动）：

- **dataOp 统一客户端投影**：list、add、update 返回同一个客户端记录投影，在现有记录字段之外新增布尔字段"是否由当前调用者创建"，由云端按调用者身份计算。投影不再包含创建者 openid、房间码和创建时间。
  - 现在 list 返回的是原始文档；前端没有任何地方读取创建者字段，可以直接收紧。
- **兼容性**：旧客户端会忽略新字段；授权语义（records 只看 rooms）不变。前端没有任何地方读取创建时间，可以一并收紧。
- **欢乐时光日期**：同一次改动里，dataOp 对欢乐时光的日期拒绝未来日期。
- **部署**：只需要部署 dataOp，不在房间生命周期的维护窗口发布序列里。
- **客户端显示**：只在房间已配对时，在列表行和当日详情里显示"我记的 / TA 记的"。

错误文案（roomAccessOutcome、room 会话、recordCommands、settingsFlow）：

## Testing Decisions

好测试的标准：只验证外部可观察的行为，包括纯函数的输入输出、页面数据和用户能看到的文案、模板与样式的契约，不测试实现细节。每条用户故事都至少落在下面某一个接缝上。接缝全部沿用现有的，不新增；新增的纯函数都放在已有模块的接口上。

- **领域投影接缝**（纯模块，首选）：
  - homeCalendarState：
    - 经期段位：起点、中段、终点、单日、开放端；跨周收口；与今天、欢乐时光的叠加；
    - 图例项与格内标记描述同源；
    - 农历显示规则；
    - 详情去掉说明卡，记录行带编辑目标；
    - 读屏名。
  - cycle：首页状态行的状态与文案；完成默认结束日为今天；预期时长上限提示的阈值。
  - recordEditRoute：新增的过去记录是"已结束 + 结束日为空"；完成进行中记录的默认值。
  - calendarInsights：预测说明首句、口语置信度、非医疗建议说明、小结去重。
  - util：唯一的日期显示格式，包括跨年和区间写法。
  - roomAccessOutcome：任何结果都不向用户输出原始技术字符串。
  - memoryMonthGroups：默认展开三个月、摘要。
  - 先例：home-calendar-state、cycle-prediction、record-edit-route、calendar-insights、calendar-display、calendar-micro-labels、room-access-outcome、record-draft 测试。
- **页面接缝**（沿用首页测试里 loadPageHarness 的页面装载方式，以及记录流程、设置流程、绑定流程测试的做法）：
  - 首页：CTA 随状态变化；"为某天记经期"的单一决策与提示；直达详情；详情行打开编辑；超期提醒的持久化时机；下拉刷新；回到今天；选月即跳；滑动翻月处理；弹层期间的 tabBar 与系统返回；首次欢迎条；"TA 已加入"一次性提示；本月小结行。
  - 经期编辑页：默认值、校验文案、重叠确认、删除确认的按钮文案、保存未确认时的自动核对。
  - 欢乐时光编辑页：未来日期校验；当日弹层在未来日子不出现记录动作。
  - 设置页：分组与危险区、重新同步房间、成员状态、解绑确认文案与成功提示、导出文案、使用说明。
  - 绑定页：分享参数预填、已绑定时忽略参数、恢复提示、解绑后提示。
  - 记录 tab：默认展开与摘要、兼容路由跳转、作者显示。
  - 先例：index-page、record-flow、settings-flow、bind-room-flow、page-registration 测试。
- **静态模板与样式接缝**（现有护栏扩展）：
  - 对比度：把三种组合状态登记进对比度护栏和次级入口对比度测试的用例。
  - 设计 token 护栏：玻璃面上限收紧；近不透明面上不得出现 backdrop-filter；hover-class 与 `:active` 成对出现；分段控件只有一种选中态；主按钮只有一种形状。
  - 交互语义：遮罩与面板是兄弟结构；所有可点控件都有 hover-class；分享按钮带语义。
  - 窄屏几何：共享顶栏、房间码输入框高度、6 行月份在 320 / 375 / 390 下的高度账本。
  - 字号角色：状态行与新增文案的角色。
  - 动效与性能：极光层尺寸、滑动翻月与 tabBar 隐藏的减弱动效分支。
  - 新增一条模板护栏：`text` 内不得出现 `br`。
  - 先例：design-token-guardrail、contrast-guardrail、secondary-affordance-contrast、filled-cta-contrast、narrow-screen-geometry、interaction-semantics、typography-roles、typography-hierarchy、motion-performance、glass-fallback 测试。
- **云端接缝**：
  - room-records 测试覆盖：list、add、update 返回同一个客户端投影；包含"是否由当前调用者创建"；不包含创建者 openid、房间码和创建时间；欢乐时光的未来日期被拒绝。
  - data-op-auth 测试保持不变，作为授权语义没有变化的证明。
- **人工验收**：用开发者工具截图，在 390 和 320 两种宽度下覆盖以下状态：
  - 未绑定的创建 / 加入（用视图态模拟，房间码为假值）；
  - 首页当月和一个 6 行月份；
  - 各个弹层；
  - 两个编辑页；
  - 设置页。

  截图不入库，也不含房间码、真实日期和备注。真机、读屏实听、系统减弱动效如果无法验证，就在 `docs/verification-log.md` 的条目里写成未验证项。

## Out of Scope

- 删除后撤销：需要云端恢复语义，现有确认框已经说明不可恢复。
- 在云端合并或硬性拦截重叠的经期记录：CONTEXT.md 把它定为另行处理的数据质量问题，本 spec 只在页面层引导。
- 预测算法和统计口径本身：周期计算、波动天数、样本选择都不改，只改呈现和文案。
- 房间生命周期四个云函数的任何改动，以及 getMyRoom 返回整份房间文档（含双方 openid）这件事的投影收紧：本 spec 只收紧记录投影，房间投影另立。
- 重做视觉世界：Aurora Bloom、暗色唯一主题、系统字体、玫瑰 / 薰衣草 / 金色板都保留，不引入外部品牌设计系统。
- 提醒推送和订阅消息、照片附件、多房间、浅色主题。
- 医疗建议或健康判断。
- impeccable 检测器的项目配置：它属于本地工具状态（git-ignored），要不要配置由用户决定。
