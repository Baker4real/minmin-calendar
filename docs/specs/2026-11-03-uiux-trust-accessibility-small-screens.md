# UI/UX 信任、无障碍与小屏收口

**Date:** 2026-11-03
**Status:** Accepted
**Issue:** #148

## Problem Statement

两个人使用这个小程序时，核心目标不是欣赏一套深色皮肤，而是：扫一眼就相信日历表达的事实；第一次加入就知道彼此已经连上并看懂标记；记录被中断或网络失败时能恢复；导出私密内容时不发生预期外的复制；在小屏、读屏和减弱动效下仍能完成同一件事。

现行 Aurora Bloom、双人 Room、三态经期、预测与实录分离、记录作者、草稿恢复和日历标记体系已经形成稳定基础。上一轮全面 UI/UX 收敛已经解决了大量通用问题，本次不再重做视觉世界，也不把检测器伪影当成新需求。

本次评审确认的剩余问题集中在六个 failure modes：

1. **首次连接的情绪峰值和标记教学可能不可见。** 一次性配对欢迎条位于固定吸顶区的覆盖范围内，而已读标记在展示时立即消费，TA 可能从未看到连接确认和图例解释。
2. **核心日历的几何契约只分别检查“行高”和“内容”，没有检查两者同时成立。** 在 320/375 短屏、六行月份、显示「回到今天」时，动态行高可能小于格内声明内容所需高度，最终由 flex 压缩或裁切吸收。
3. **私密导出的失败回退越过用户意图。** 分享失败会自动把全部经期和欢乐时光 JSON 写入剪贴板，用户在导出前没有同意这一后果。
4. **视觉模态不等于完整模态。** 设置帮助缺可见关闭键、系统返回协调和一致的退出生命周期；首页与设置弹层的读屏边界、背景隔离和焦点返回没有形成统一契约。
5. **异常和边界状态没有始终给出下一步。** 部分同步失败持续显示状态但没有直接重试；普通未来日期可能打开无正文、无动作的弹层；首页空态仍引导用户点「任意一天」。
6. **剩余视觉与语义细节削弱扫读。** 周期概览小字在实际渐变合成底上略低于 4.5:1；预测措辞略带保证感；表单校验主要依赖瞬时 toast；同日多条记录读屏名不可区分；创建成功后的双主按钮、铅笔「记录」图标、圆点经期快捷符号和月份边界静默不动作仍有局部不一致。

约束与不能破坏的事实：

- Room 最多两人，数据只在房间内共享；公开 issue、截图和验证证据不得包含真实日期、备注、房间码、成员身份或其他私密内容。
- 记录日期不能晚于今天；未来日期的预测、节日和调休仍应可查看。
- 进行中、结束日期不详、已结束三态不变；不猜结束日，不自动关闭进行中记录。
- Overlap day 只表达经期；预测窗口、首页状态行、图例和预测说明继续存在。
- 一个视觉符号只表达一个含义；经期是玫瑰连续色带，欢乐时光是浅粉 ♥，「预」是下次可能开始的日子。
- Aurora Bloom、暗色唯一主题、系统字体、玫瑰／薰衣草／金色板、现有减弱动效和按压政策继续沿用。
- 当前工作树里正在收紧的经期色带和「今天＋经期」样式是现行基线，不为迎合旧截图回退。

## Solution

从用户角度看，完成后的产品应表现为：

- TA 加入后，在首页实际看得到一次「已和 TA 连上」及标记说明；只有欢迎条真正进入已渲染页面才记为已读。
- 日历在短屏上优先保住日期、经期、欢乐时光、预测、节日和调休的完整表达。清爽密度在空间不足时合并节日／调休与标记行；仍不足时允许下方内容滚动，不裁切格内信息，状态行始终可见。
- 导出分享失败时，由用户明确选择「重试分享／复制 JSON／取消」；不发生未经确认的剪贴板写入。
- 设置帮助和首页弹层具有一致的可见关闭、系统返回、tabBar、读屏和焦点行为；减弱动效下仍即时到位。
- 部分同步失败会直接显示可点重试；未来日期弹层会解释为什么不能新增记录，同时保留预测和节日信息。
- 表单错误留在对应字段旁；记录列表和当日详情的读屏名能区分同日多条记录。
- 预测措辞只描述可能窗口，不做健康保证；关键小字在实际表面上达到对比度要求。
- 创建成功后只有一个主行动；底部「记录」图标表达列表；经期快捷动作与日历色带同形；月份到边界时给出禁用状态。
- 所有变化都有当前微信运行态证据，而不是只依赖静态测试、旧截图或 detector 空命中。

## User Stories

### 首次配对与首页引导

1. 作为刚加入 Room 的 TA，我希望首页明确显示「已和 TA 连上」，以便确认双人共享已经开始。
2. 作为第一次看日历的用户，我希望连接成功时同时看到经期色带、♥ 和「预」的简短解释，以便不必先猜测标记含义。
3. 作为首次使用者，我希望欢迎条不被月份导航或状态行遮住，以便真正读完这次引导。
4. 作为首次使用者，我希望欢迎条没有成功显示时不会被记为已读，以便下次仍能获得这次说明。
5. 作为已经看过欢迎条的用户，我希望它不会反复出现，以便日常首页保持安静。
6. 作为创建房间的人，我希望创建成功后「发给 TA」是唯一主按钮，以便立刻完成最重要的配对动作。
7. 作为创建房间的人，我希望「进入应用」是清楚的次级操作，以便想先看日历时不被阻断。
8. 作为首页跳转失败的已绑定用户，我希望此时「进入应用」仍能成为主要恢复动作，以便不被创建成功页的层级规则限制。

### 小屏日历与信息完整性

9. 作为用 320px 短屏手机的人，我希望日期、经期和欢乐时光标记不被裁切，以便相信日历显示的是完整事实。
10. 作为用小屏手机的人，我希望节日、「班」和「预」在清爽密度下仍可读，以便不遗漏已有上下文。
11. 作为使用完整密度的人，我希望农历行不会挤压日期或标记，以便额外信息不损害核心信息。
12. 作为查看六行月份的人，我希望每一格都遵循同一套高度与内容账本，以便月末不会出现异常行。
13. 作为翻到非当月的人，我希望「回到今天」出现时日历仍正确排版，以便额外操作不破坏布局。
14. 作为查看经期色带的人，我希望单日、连续段、跨周收口和开放端在小屏仍保持原有语义，以便区分记录状态。
15. 作为查看「今天＋经期」的人，我希望日期与色带描边完整可见，以便同时识别今天和经期。
16. 作为查看 Overlap day 的人，我希望格子仍只表达经期，以便小屏重排不会重新叠加「预」。
17. 作为单手操作用户，我希望日历格仍保持至少 44px 的触控高度，以便不通过缩小格子来容纳内容。
18. 作为查看首页的人，我希望月份和首页状态行始终可见，以便滚动后仍知道当前上下文。
19. 作为想快速记录的人，我希望空间足够时记录入口仍在首屏，以便减少滚动。
20. 作为使用极短屏的人，如果首屏无法同时容纳完整日历和记录入口，我希望下方自然滚动，而不是牺牲格内内容或触控尺寸。

### 私密导出与用户意图

21. 作为导出数据的人，我希望在开始前知道会导出全部经期和欢乐时光，以便判断分享对象是否合适。
22. 作为取消系统分享面板的人，我希望剪贴板保持原样，以便取消真正意味着没有后续动作。
23. 作为分享失败的人，我希望看到「重试分享／复制 JSON／取消」，以便自己决定如何处理私密内容。
24. 作为分享失败的人，我希望系统不要自动复制完整 JSON，以便私密记录不会在我不知情时进入系统剪贴板。
25. 作为明确选择「复制 JSON」的人，我希望复制成功后看到明确反馈，以便知道下一步可以粘贴保存。
26. 作为导出失败的用户，我希望原有网络、房间状态变化和重新绑定恢复路径继续有效，以便本次隐私调整不破坏错误恢复。

### 弹层、读屏与系统控制

27. 作为打开设置「使用说明」的人，我希望看到明确的关闭按钮，以便不必猜测点击遮罩。
28. 作为使用 Android 系统返回的人，我希望设置帮助先关闭再考虑离页，以便不会意外丢失当前页面上下文。
29. 作为打开设置帮助的人，我希望底部 tabBar 不会误触切页，以便保持当前任务。
30. 作为开启减弱动效的人，我希望设置帮助立即打开和关闭，以便不等待过渡。
31. 作为读屏用户，我希望弹层有可读名称和明确角色，以便知道当前进入了一个新上下文。
32. 作为读屏用户，我希望弹层打开时背景内容不再被继续朗读，以便只处理当前面板。
33. 作为读屏用户，我希望遮罩「关闭」与面板内控件分别可达，以便不会把整个面板误听成一个关闭按钮。
34. 作为读屏用户，我希望关闭弹层后焦点回到原触发器，以便继续原来的操作路径。
35. 作为使用首页任意底部 sheet 的人，我希望月份选择、当日操作、工具、图例、预测说明和小结遵循同一模态边界，以便形成稳定预期。
36. 作为使用微信不同版本的人，我希望无障碍语义只使用当前平台真实支持的能力，以便不会因为声明了 ARIA 属性却实际无效而被误导。
37. 作为使用 VoiceOver 或 TalkBack 的人，我希望主要弹层流程经过实际朗读验证，以便不仅能看见关闭键，也能听到并操作它。
38. 作为被弹层手势打断的人，我希望现有拖动、反向进出和系统返回行为不回退，以便新增关闭键不会破坏已有控制感。

### 同步失败与未来日期

39. 作为首页只有经期同步失败的人，我希望看到旧经期数据仍在以及「点按重试」，以便直接恢复。
40. 作为首页只有欢乐时光同步失败的人，我希望看到已加载内容和明确重试，以便不必发现隐藏手势。
41. 作为读屏用户，我希望同步状态变化与重试入口分别被朗读，以便理解状态和可执行动作。
42. 作为网络恢复后重试的人，我希望成功后重试行消失且日历更新，以便确认数据已经恢复。
43. 作为重试仍失败的人，我希望旧数据和失败说明继续保留，以便不会反复丢失上下文。
44. 作为点击普通未来日期的人，我希望看到「未来日期不能新增记录」的说明，以便不会把空弹层当成故障。
45. 作为查看未来预测或节日的人，我希望仍能打开未来日期并看到这些信息，以便记录禁令不妨碍查看。
46. 作为第一次使用首页空态的人，我希望文案引导我点今天或过去的一天，以便不会先尝试一个注定不能记录的未来日期。

### 表单、记录辨识与文案

47. 作为填写日期有误的人，我希望错误持续显示在对应字段下，以便分心后仍能知道要修哪里。
48. 作为读屏用户，我希望字段错误与输入控件关联，以便能听清错误属于开始日、结束日还是欢乐时光日期。
49. 作为表单校验失败的人，我希望已有输入和草稿不丢失，以便修正一个字段即可继续。
50. 作为编辑记录的人，我希望现有保存、删除、重叠确认和未知结束日语义不变，以便 inline 错误不会改变领域事实。
51. 作为在同一天有多条欢乐时光的人，我希望当日详情每条的读屏名包含备注摘要和作者，以便选择正确记录。
52. 作为编辑同日多条经期记录的人，我希望读屏名包含日期区间、状态和作者，以便区分名称相同的编辑入口。
53. 作为浏览欢乐时光月份分组的人，我希望每行读屏名除日期外还包含备注摘要和作者，以便不必逐行展开猜测。
54. 作为查看预测说明的人，我希望看到「前后 N 天是可能开始的窗口」，以便理解它是估算范围而不是健康保证。
55. 作为担心周期波动的人，我希望继续看到「根据记录估算，不是医疗建议」，以便不会把日历估算当成诊断。

### 视觉一致性与细节

56. 作为查看周期概览的人，我希望「平均周期／平均持续」等标签在实际渐变背景上清楚可读，以便快速扫读统计。
57. 作为低视力用户，我希望承载操作后果或记录内容的辅助文字不弱于现行次要文字档，以便不因氛围透明度丢失信息。
58. 作为使用应用的人，我希望装饰性和非关键文字不被机械统一成同一透明度，以便保留 Aurora Bloom 已有的细致层级。
59. 作为看底部 tab 的人，我希望「记录」使用列表或档案图标，以便图标与记录列表的实际内容一致。
60. 作为使用底部 tab 的人，我希望新图标保持 81×81、未选中灰色和选中玫瑰色，以便不破坏现有导航契约。
61. 作为使用首页「记经期」的人，我希望按钮符号是小型经期色带，以便把动作与日历标记直接对应起来。
62. 作为从当日操作记录经期的人，我希望动作符号也使用同一色带样本，以便不同入口不占用另一套圆点语义。
63. 作为使用欢乐时光入口的人，我希望 ♥ 的形状、颜色和含义保持不变，以便本次图标调整不引入第二套欢乐时光符号。
64. 作为翻到最早或最晚月份的人，我希望相应箭头显示禁用且不可操作，以便知道已经到达边界。
65. 作为读屏用户，我希望月份边界箭头朗读禁用状态，以便不会反复点按没有反应的控件。
66. 作为视觉敏感用户，我希望本次不新增常驻动画、辉光或渐变 CTA，以便改动只改善识别和层级。

### 验证与维护

67. 作为维护者，我希望每条用户故事都落在现有纯函数、页面 harness、模板/样式护栏或运行态验收之一，以便测试不绑定实现细节。
68. 作为维护者，我希望日历行高与格内内容容积联合测试，以便分别正确的两个模块不会在组合后裁切。
69. 作为维护者，我希望当前 320/375/390/430 视口证据回读真实微信 windowWidth/windowHeight，以便不从图片尺寸推断验收范围。
70. 作为维护者，我希望真机读屏、字体放大、系统减弱动效、键盘顶起、触控命中和低端 Android 性能有明确结果或未验证记录，以便报告不夸大完成度。
71. 作为项目维护者，我希望公开证据只使用替身数据或裁到被测控件，以便真实房间和记录不会进入公开仓库。
72. 作为后续实现 Agent，我希望 DESIGN、验证日志和必要的领域文档随实际行为更新，以便不会同时存在两套现行规则。

## Implementation Decisions

### 领域与视觉边界

- 不改变 Room、Record、Period status、Prediction、Overlap day、Today、Memory month group 的领域定义。
- 不改变预测算法、周期统计、记录作者投影、云端授权、数据库 schema 或任何云函数。
- 不改变未来记录禁令、进行中唯一性、重叠记录的页面层引导、结束日期不详语义和草稿键规则。
- 保留现行经期色带与「今天＋经期」实现，不回退到旧整格色带或旧截图。
- 保留 Aurora Bloom 的色板、圆角、字号角色、按压、减弱动效、玻璃和阴影注册表；新增样式必须使用既有 token 和语义护栏。

### 首次配对与创建成功层级

- 欢迎条移到首页吸顶占位之后的正常文档流，避免覆盖月份导航、状态行和日历。
- 一次性欢迎的消费时机从「逻辑层决定展示」收紧到「欢迎条已提交渲染」；首页未进入可显示状态时保留待展示标记。
- 继续使用现有一次性 Room presence 存储与页面状态，不增加第二种配对提醒。
- 创建成功时分享是主行动，进入应用是次级行动；仅发生首页跳转失败且不是刚创建时，进入应用可以是主恢复行动。
- 欢迎条出现后的额外高度必须进入首页几何账本，不得把日历内容再次压到不可读。

### 日历几何与短屏降级

- 继续以现有日历行高计算模块作为唯一几何计算出口，扩展它同时考虑视口、导航高度、密度、行数、「回到今天」、一次性欢迎和格内内容最小高度。
- 现有页面 CSS 仍负责实际槽位尺寸；几何模块与样式测试共享同一份可验证账本，不另建第二套尺寸来源。
- 清爽密度在空间不足时把节日／调休与欢乐时光／预测标记合并为一个底部信息行；所有已有信息继续显示，读屏名不变。
- 完整密度优先保留日期、经期、欢乐时光、预测、节日和调休，再保留农历；不得通过低于现行字号下限或裁切来塞入内容。
- 当内容最小高度与首屏记录入口无法同时满足时，采用页面滚动，保持状态行吸顶、记录入口可达和日历格至少 44px 高。
- 日历格宽度、七列平铺、连续色带、Overlap day 抑制和滑动翻月阈值不变。

### 首页异常与未来日期

- 部分集合失败复用现有行内重试状态和处理器，不把同步状态胶囊改造成按钮。
- 重试文案指出失败集合；旧数据、部分数据和 pending revision 的现有协调逻辑保持不变。
- 只有明确成功重试后才清除行内失败状态；连续失败不自动隐藏。
- 无记录的未来日期继续使用当日弹层，但 actions 模式显示持久解释；不新增任何未来记录动作。
- 未来日期的预测、节日和调休说明继续由现有日历投影提供。
- 首页空态只引导到今天或过去日期，不模糊成「任意一天」。

### 弹层与无障碍

- 设置帮助接入与首页 sheet 相同的打开、离开、系统返回、tabBar 和减弱动效语义，不引入第二套计时器或第三方弹层库。
- 设置帮助增加可见关闭控件，触控高度沿用通用 88rpx 档；遮罩仍是独立关闭操作。
- 首页和设置弹层使用微信当前支持的角色与名称表达模态；背景隔离、朗读顺序和焦点返回必须以真实平台能力为准。
- 如果微信不支持某个标准 ARIA 模态属性，不伪造支持结论；使用可达的替代结构，并把限制记入验证结果。
- 关闭后焦点回到触发器；若平台不支持程序化焦点，记录限制并确保读屏顺序仍有确定落点。
- 现有底部 sheet 的拖动、交接、反向过渡、装饰暂停和遮罩层级不回退。

### 私密导出

- 分享成功保持原反馈；用户取消分享直接结束且不触碰剪贴板。
- 分享失败只返回可识别的失败结果，由设置流程展示「重试分享／复制 JSON／取消」。
- 只有显式复制动作调用剪贴板 API；复制前不再次弹出含义重复的确认。
- 保留导出前确认、全量成功语义、房间访问错误分类和重试／重新绑定路径。
- 不增加导入、自动备份、系统分享扩展或云端导出。

### 表单、记录名称与预测文案

- 现有共享记录命令适配器继续负责校验结果和保存生命周期；页面把可定位的校验结果显示在对应字段旁。
- 校验失败不写云端、不清空输入、不清除草稿；保存和删除按钮的既有防重复行为不变。
- 错误文本使用普通语言，并与字段建立读屏关联； toast 可保留给无法定位到字段的整体错误。
- 当日详情和欢乐时光列表的读屏名由现有投影／分组模块提供足够区分信息；可见 UI 不额外堆叠重复元数据。
- 备注摘要只使用必要长度，空白备注跳过；作者仍只在 Room 已配对时出现。
- 预测首句改为描述「可能开始的窗口」，算法、窗口天数和非医疗建议声明不变。

### 对比度、图标与边界状态

- 周期概览标签提升到现有 secondary 文字档；对比度按实际画布、玻璃回退和渐变端合成后的表面计算。
- 只提升承载操作后果、记录内容或关键说明的辅助文字；不机械合并现行逐元素透明度。
- 底部「记录」两态图标改为列表／档案语义，保留 81×81 PNG、颜色对和资源预算。
- 首页经期快捷动作与当日经期动作复用图例的色带样本类和颜色，不新增圆点或第二种玫瑰语义。
- 欢乐时光 ♥、预测「预」、今天、节日和调休的形态不变。
- 月份箭头在边界年/月同时获得视觉禁用、事件禁用和读屏禁用；滑动翻月到边界保持安静，不弹错误。
- 不为 320px 下所有通用控件另建固定 px 尺寸体系；先在真机记录实际命中问题，若需要修改现行 88rpx 口径，另立设计规范决策。

### 文档与交付

- 视觉形态、对比度或图标契约变化时更新 DESIGN 的单一权威条目，不保留目标稿与实现基线两套描述。
- 领域含义没有变化时不改 ADR；若实现必须改变三态、Overlap day 或未来记录规则，先停止并补 ADR，而不是在实现中静默变更。
- 本规格按 epic 级改动处理，完成时在验证日志追加测试数、证据范围、未验证项和云函数未变更说明。
- 不新增测试框架、UI 组件库、设计系统包或 detector 配置。

## Testing Decisions

好测试只验证外部可观察行为：纯函数输入输出、页面数据、用户可见文案、实际渲染结构、模板与样式契约、真实运行态可达性。不把私有函数调用次数、具体 DOM 实现或旧截图当作行为本身。优先使用现有接缝，不新增平行测试入口。

### 1. 领域投影与纯函数接缝

- **homeCalendarState**：普通未来日期无记录动作但有解释所需状态；预测／节日仍可查看；Overlap day 仍抑制格内预测；同日多条记录的读屏区分信息；图例与动作色带样本同源。
- **calendarRowHeight**：行高、内容最小高度、记录入口是否入屏和是否需要滚动在同一组输入下联合断言；覆盖两种密度、五/六行、「回到今天」和欢迎条。
- **calendarInsights**：预测首句只描述可能窗口，保留非医疗建议，不改变窗口数值。
- **memoryMonthGroups**：欢乐时光行读屏名包含日期、非空备注摘要和配对后的作者；空白备注不制造多余标点。
- 先例：现有 home-calendar-state、calendar-display、calendar-micro-labels、cycle-prediction、calendar-insights、memory-month-groups 相关测试。

### 2. 页面行为接缝

- **首页 harness**：欢迎条位置与一次性消费、部分集合失败重试、未来日期弹层、空态文案、月份边界禁用、弹层背景与关闭后状态。
- **设置流程 harness**：分享成功／取消／失败三路径；只有显式复制才写剪贴板；设置帮助的可见关闭、系统返回和 tabBar 协调。
- **记录流程 harness**：字段级校验、输入和草稿保留、保存／删除生命周期不回退。
- **绑定流程 harness**：刚创建与首页跳转失败两种场景的按钮层级和动作不变。
- 先例：index-page、settings-flow、record-flow、bind-room-flow 的现有页面装载方式。

### 3. 模板、样式与资源护栏

- **interaction-semantics**：可见关闭键、遮罩与面板角色、背景隔离的可用表达、记录读屏名、月份边界 aria-disabled；不以属性存在替代真机读屏验收。
- **narrow-screen-geometry 与 calendar-micro-labels**：把动态行高和实际槽位高度合并成同一账本，覆盖 320/375/390 的短屏与六行月份。
- **contrast-guardrail 与 secondary-affordance-contrast**：周期概览实际渐变合成底、关键辅助文字和新增次级「进入应用」。
- **tab-icons 与 tracked-images**：新记录图标的尺寸、两态颜色、非医疗十字／非铅笔语义和上传资源边界。
- **design-token、typography、motion-performance、glass-fallback**：确保新色带样本、关闭键、次级按钮和设置 sheet 不绕过现行规范。
- detector/HTML shim 只作补充信号；所有命中必须回源复核，不能把 55 条历史伪影或白名单设计转成工作量。

### 4. 微信运行态与真机验收

- 使用当前微信开发者工具，回读实际 windowWidth/windowHeight；320×568、375×667、390×844、430×932 是最小覆盖集合。
- 日历覆盖完整／清爽、六行、是否显示「回到今天」、单日、连续段、开放端、今天＋经期、Overlap day、节日和调休。
- 首页覆盖首次加入欢迎、空态、noRoom、骨架、部分同步失败、普通未来日期、各弹层、系统返回和实际坐标点击。
- 两个编辑页覆盖新增／编辑、草稿恢复、字段错误、长备注、键盘顶起、保存／删除中。
- 绑定和设置覆盖创建／加入／邀请、首页跳转失败、设置帮助、导出取消／失败／明确复制、解绑和恢复。
- 真机覆盖 VoiceOver／TalkBack、字体放大、系统减弱动效、触控命中和低端 Android 的基本流畅度；不可用项必须明确记录。
- 所有公开截图使用替身数据或裁到被测控件；真实日期、备注、房间码和成员信息不上传。
- 完成前运行项目统一 `verify` 入口和 `git diff --check`；坐标回归和本地测试不能替代上述微信验收。
