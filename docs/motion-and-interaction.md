# Aurora Bloom 动效与交互

本文从 `DESIGN.md` 下沉出来，和它一起是 Aurora Bloom 的唯一现行视觉说明。缓动、时长与延迟，翻月滑入与日历强调，记录成功反馈，弹层的进出、错相、交接与遮挡暂停，同步胶囊与失败恢复，按压与交互态，读屏语义，以及常驻与一次性两张动效注册表，以本文为准。色板、材质、圆角、间距、字号、布局、日历格状态和 frontmatter token（含 `modal-overlay`）仍在 `DESIGN.md`。不要并列第二套「目标稿」或「实现基线」；已审查数值不要按旧稿回改。

## 规则

已在屏幕上成立、改 UI 时沿用：

- 交互语义（issue #57）：每个可点控件（bindtap/catchtap，sheet 的 `catchtap="noop"` 泄泡盾除外）都带 `aria-role` 与可读 `aria-label`；弹层遮罩本身是「关闭」操作，按用途命名（关闭月份选择/当日操作/工具菜单/日历图例/预测说明/本月小结/使用说明）。选中态用 `aria-checked` 表达并与 `active` 类同条件绑定（单选组如经期状态、密度、月份格、绑定 tab 用 `radio`，可多选或可再点取消的经量/症状 chip 用 `checkbox`）；禁用与加载态用 `aria-disabled` 表达并与 `disabled`/`loading` 类同条件。可看的月份是 2001 年 1 月到 2035 年 12 月，与选月的年份范围是同一对常量（issue #159）：到了一端，那一侧的月份箭头禁用，透明度 0.35，按下不缩放、不着色，`aria-disabled` 与 `disabled` 同条件；点按和滑动都不翻月，也不提示。picker 与输入框带 `aria-label`。首屏加载指示（`.loading-spinner`）带可读 `aria-label`；同步状态胶囊（`.sync-pill`）为 `status` 角色、朗读名与 `syncStatusText` 同源，同步状态变化即可朗读（issue #106）。日历格保持 `aria-label="{{item.ariaLabel}}"` 领域朗读（日期+经期/欢乐时光/预测/节日/调休）与 `aria-hidden="{{item.isEmpty}}"` 空白格隐藏，角色为 button；语义文案唯一来源仍是 `utils/homeCalendarState.js`。弹层读屏模态（issue #155）：首页六个底部弹层与设置「使用说明」用同一套表达。面板本体不写 `aria-role`，只有读屏名，是弹层用途（月份选择、当日操作、工具菜单、日历图例/预测说明/本月小结、使用说明；信息弹层随当前内容取 `infoSheetName`），遮罩读「关闭」加同一名称。模态上下文由遮罩名、面板名和被隐藏的背景三者给出，不靠角色。宿主里只有遮罩和面板，读屏顺序固定为遮罩 → 面板名 → 标题行（标题、副标题、「关闭」）→ 面板内控件。任一弹层处于 open 或 leaving（含交接）时，页面根下的背景块（顶栏、未绑定/加载失败、骨架、内容）`aria-hidden` 与 `page-obscured` 同一状态，最后一个弹层卸载的同一次更新里恢复；弹层宿主直接挂在页面根下，不在被隐藏的块里。平台边界以微信 aria-component 文档为准（https://developers.weixin.qq.com/miniprogram/dev/component/aria-component.html）：基础库 2.7.1 起只支持部分 ARIA 标签；可设的 `aria-role` 参照 MDN「Widget Roles」，部分 role 在移动端可能无效，dialog 不在其中，所以面板不写这个角色；文档列出 `aria-modal` 却没说行为，不写，背景隔离只靠 `aria-hidden`。微信没有把读屏焦点移到某个 view 的接口（`wx.checkIsOpenAccessibility` 只回答读屏是否开启），关闭后焦点落点由系统决定，不保证回到触发器；能保证的是背景按原文档顺序恢复，触发器名称和位置不变，从工具菜单交接出的图例/预测说明/本月小结，原触发器是顶栏最前的「工具」。属性写对不等于读屏可用，VoiceOver/TalkBack 实听结果以验证记录为准。护栏：`tests/interaction-semantics.test.js`、`tests/index-page.test.js`、`tests/settings-flow.test.js`。
- 展开/收起文字入口（issue #109，「记录」tab 欢乐时光月份卡头）：切换入口用文字「展开」/「收起」，不用字形——「›」已用于列表行「点开编辑」（`.item-arrow`/`.memory-arrow`），「⌄」已用于首页选月 caret（`.month-title-caret`），不重复占用；文字自述点按后果。卡头按 button 朗读，`aria-expanded` 与展开状态同条件，读屏名「YYYY年M月，N 条欢乐时光，已展开/已收起」；收起且该月有备注时，在状态前加上该月第一条备注的单行摘要（从新到旧，跳过空白备注；整月没有备注则不追加）。摘要显示在卡头标题下方，单行，超出截断，展开时不重复渲染，可见文字 `aria-hidden`，读屏只走卡头名。点按即时切换、无过渡动画（不进动效注册表，开启减弱动效时无差别）。文字走 caption 角色（26rpx）+ `var(--text-secondary)`，在月份卡（`.premium-card`）表面 ≥4.5:1，护栏 `tests/secondary-affordance-contrast.test.js`（CASES 登记）；320px 单行账本由 `tests/narrow-screen-geometry.test.js` 钉住。这是应用里第一个展开/收起交互，本条即先例。
- 经期月份展开/收起（issue #187）：沿用欢乐时光的文字操作、button 角色与 `aria-expanded`，读屏名为「YYYY年M月，已展开/已收起，收起/展开经期记录」。年份标题同样是文字展开／收起入口，朗读名为「YYYY年，已展开/已收起，收起/展开经期记录」，触控高度至少 88rpx。年份和月份默认全部展开，分别保留页面内手动选择；收起年份不清空月份选择。点击即时切换、无动画，收起后不渲染记录行；手动选择只保留在页面内存，刷新与切换分段保留，页面重新创建恢复默认。按记录身份进入编辑；确认保存后展开开始日期所属年／月，开始年月改变时移组，删除后移除空月与空年。取消或保存失败不改变分组选择。
- 动效与性能边界（issue #58）：缓动只有 `--ease-out`（`cubic-bezier(0.16,1,0.3,1)`）与标准关键字（ease/ease-in-out/linear 等）；bounce/elastic 式 overshoot 曲线（cubic-bezier 的 y 参数超出 0–1）与 `--ease-spring` / `--transition-spring` token 已退役，bind 页 `bounceIn` 回弹入场同步改为无回弹的 `heroIn`，禁止同类曲线以任何命名回归。一次性时长只有六档 app 级 token（issue #111；第六档由 issue #165 加入）：`--duration-press` 160ms（可点控件按压的四路：缩放、底色、描边与柔光层透明度，见「按压的四路」；阴影本身不进过渡）、`--duration-state` 200ms（选中、颜色、描边、焦点边框，后台刷新时日历变暗，以及当日详情的淡入 `dayDetailFade`）、`--duration-enter` 240ms（整页淡入 `pageEnter`、弹层遮罩淡入、弹层内容块进场、同步胶囊入场、翻月滑入、绑定页显现 `bindReveal`）、`--duration-exit` 200ms（弹层面板、内容块与同步胶囊离场，遮罩淡出）、`--duration-sheet` 280ms（弹层面板升起）、`--duration-emphasis` 600ms（今天与「预」的一次性光晕，亮起再落回；记录成功的 ♥ 与色带、建好房间时绑定页 ♥ 的漾开，issue #167）。延迟只有一档 `--delay-stagger` 40ms，只给弹层内容块进场错相用（issue #166，见下文「弹层标题与内容错相」），别的 transition 不写延迟；时长、曲线和延迟都只写在 `transition` 简写里，不写长写。一次性关键帧动画的延迟也只有一档 `--delay-return` 300ms，只给记录成功反馈等返回转场走完（issue #167，见下文「记录成功反馈」），别的一次性动画不写延迟，延迟同样只写在 `animation` 简写里。按压只属于可点控件，容器和不可点的行不缩放、不变底色（issue #113，取代 issue #81 的逐页豁免）。微信里每个可点控件（`bindtap`/`catchtap`，`catchtap="noop"` 除外）都带 `hover-class`，并且和对应的 `:active` 写在同一条规则里，开发者工具才会画出按压（issue #122，issue #145）。类名重复控件自己的类，例如月份箭头 `nav-btn-hover`，危险行 `danger-hover`，危险按钮 `btn-danger-hover`，返回键 `nav-back-hover`。按压着色落在可以过渡的 `background-color` 上（海军实底之上的平涂层），时长仍是 `--duration-press`，不写进 `background-image`。方向仍是 issue #122 的海军实底上平涂着色。`:active` 规则保留。位移、缩放、入场、离场用 `var(--ease-out)`；只变颜色或底色用 `ease`；导航头光斑 `float` 的来回漂移用 `ease-in-out`（周期仍是 8s 与 6s）。除 `--ease-out` 定义外不写 cubic-bezier。组合变量 `--transition` 已退役。常驻动画周期、减弱动效替代和 `heroIn` 0.6s `animation` 简写里，不写 `animation-duration` 长写；错开起点用负延迟。玻璃 blur：哪些面模糊见 `DESIGN.md`「玻璃叠层」的登记；单面 ≤20px，全屏遮罩 ≤8px（两个弹层遮罩都是 `DESIGN.md` frontmatter `modal-overlay` 登记的 8px，88% 海军底上更大的 blur 政策：去掉位移、缩放、旋转的过渡与动画以及装饰动画（位置和大小直接落到终态），状态反馈走无位移通道——加载=透明度脉冲（不静默）、同步中=玫瑰点静态色、骨架=静态哑光占位块、按压=即时 scale + 既有底色变化、弹层=进出立即到位、88% 海军遮罩保留层级（issue #116）、日历切换=即时替换（翻月滑入为 且大于竖直位移才翻月，否则留给轻点和竖向滚动；不跟手，松手后一次页面更新完成，和箭头翻月同一段滑入（见下条「翻月滑入与日历状态强调」）；减弱动效下即时替换。日期格不做颜色过渡。两个编辑页的边框/背景过渡由页面级 reduced-motion 块即时切换，无渐进（issue #106）。护栏：`tests/motion-performance.test.js`。

- 记录成功反馈（issue #167）：只回应真正存下的新增或完成。触发点是首页的记录回流：编辑页只在云端确认写入后通知前一页（含写入超时后回读确认已存），带的是保存后的那条记录，所以反馈的日期和色带就是同步后日历上的样子。新增欢乐时光：那一天的 ♥ 从 0.6 倍淡入长到原大（`recordBloom`）。新增经期，或给没有结束日的经期（进行中、结束日期不详）填上结束日（ADR 0007：填写结束日期完成同一条记录）：这段经期在当月投影出的每一格色带一起淡入（`recordAppear`），跨行的各段同时到位，连续段不断开；别的经期不动。不亮的：改写已有记录（含改日期）、合并到已有进行中、进行中改成结束日期不详（色带缩回开始日，不是出现）、删除、校验失败、写入失败、回读确认没存上、取消、草稿恢复（都不通知）、后台刷新和下拉刷新、从「记录」tab 进编辑页（首页收不到通知，之后刷新出来的记录不亮），以及日历还没显示时收到的通知；记录落在别的月份时当月没有可亮的。时序：通知到达时首页正被编辑页盖着，反馈类在 `page-hidden` 下按住不开始（♥ 和色带透明）；编辑页按原来的 1000ms 返回，`onShow` 去掉 `page-hidden` 后先等 `--delay-return` 300ms 让返回转场走完，再用 `--duration-emphasis` 600ms、`--ease-out` 播一次，反馈不拖慢返回、不拦点按、不改读屏名。记号是页面数据 `recordFeedback`（日期 → memory / period），挂在 `.calendar-days` 的日期格上（`record-feedback-memory`、`record-feedback-period`），图例和记录入口的样本不受影响；它只跟着那次记录变化的日历提交：再保存一次换成新的那条，不叠加；之后任何一次日历更新（翻月、选月、回到今天、带来记录变化的刷新、别的记录变化）或未绑定、加载失败画面都去掉它，翻回来不重播；确认这次保存、没有变化的刷新不打断它。首页隐藏时先收掉反馈再挂 `page-hidden`，离场途中 ♥ 和色带不消失，下次回来不重播。不用计时器。减弱动效下 ♥ 只淡入不缩放，色带照常淡入（都只动透明度）。两段动画登记在「一次性动效注册表」。护栏：`tests/index-page.test.js`、`tests/record-flow.test.js`、`tests/interaction-semantics.test.js`、`tests/motion-performance.test.js`。

- 按压的四路（issue #166）：按下时缩放、底色、描边、柔光一起变，都走 `--duration-press`（缩放用 `var(--ease-out)`，其余用 `ease`），松手按同一拍回来，没有哪一路先跳到位。描边：底色铺在控件自己的 `background` 上时，描边带画在这层底色之上，跟着一起亮；底色落在 `::before` 平涂层上的控件，平涂层只铺内边距盒，盖不到描边带，所以按下时描边同色提亮、和平涂层一起亮——月份箭头 0.2 → 0.3，首页刷新重试与记录 tab 重试行 0.1 → 0.14，提醒行 0.12 → 0.17，危险按钮与危险菜单行红 0.28 → 0.4，绑定页重试红 0.24 → 0.32（返回键原本就是玫瑰 0.28 → 0.42）。按压柔光只属于玫瑰主按钮与复制键（`.btn-premium`、`.quick-btn`、`.copy-recap`、设置与绑定页的 `.copy-btn`），画在 `::before` 柔光层上：柔光层铺满按钮、用按钮同一个圆角（`border-radius: inherit`）、`pointer-events: none`，按下时透明度沉到 0.5，和缩放同一拍；主按钮、首页记录入口和本月小结复制键的柔光层结构只写在 `app.wxss`「柔光层」一处，各按钮只写光的大小，设置与绑定页的 `.copy-btn` 是另一份同款契约；按钮本身不带阴影，按压也不换 `box-shadow`（阴影不能过渡，透明度可以）。返回键按下只换描边和底色，投影不换、随按钮一起缩；表单 picker 按下只换玫瑰描边，不加光晕。这两处原来按下时换 `box-shadow`：返回键收紧成 `0 4rpx 12rpx` 的海军投影并提亮内高光，经期与欢乐时光编辑页的日期 picker 加一圈 20px 的 10% 玫瑰光晕。#166 为了让按压各路同一拍走完去掉了它们：阴影不能过渡，按下时会先跳到位；返回键的缩放已经带着投影一起缩，picker 按下和输入框焦点同为玫瑰描边（issue #81）。epic 只说可以协调柔光，没有要求删，维护者 2026-11-08 认可不恢复；以后要恢复，就各加一层柔光层、按下时调透明度，不再换 `box-shadow`。原生分享按钮（`button.share-invite`）放开组件自带的 `overflow: hidden`，柔光层才不被裁掉；它的按压类是 `share-invite-hover`，柔光一样沉。选中态的静态玫瑰光（选月面板的当前月 `.jump-option.active`、经期编辑页选中的状态、经量和症状芯片）表示已选，不是按压柔光，按下不变（登记见 `DESIGN.md`「Shadow / overlay 登记」）。禁用与加载中的控件按下时四路都不动：不缩放、不换底色、不提亮描边、没有柔光；做法二选一，整块 `pointer-events: none`，或每一路都被 `:active.disabled` / `:active.loading` 钉回静止值。惰性变体一律用 `disabled` / `loading` 类表达，不写内联透明度：主按钮 0.55，危险按钮（删除中、不可删）0.5，月份箭头与选月年份步进 0.35，经期状态芯片与保存中的日期字段 0.5 且不接点按；日期 picker 被停用时，里面的字段同条件带 `disabled`，`aria-disabled` 写在 picker 本身。唯一例外：「记录」tab 欢乐时光卡头（issue #109）不写过渡，按压只有一层即时底色，没有第二路要对齐。减弱动效下四路都即时切换。护栏：`tests/motion-performance.test.js`；惰性变体由 `tests/interaction-semantics.test.js` 钉住。
