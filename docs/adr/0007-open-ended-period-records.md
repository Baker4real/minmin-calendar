# ADR: 经期记录允许在结束日期未知时保存

**Status:** Accepted
**Date:** 2026-09-29

经期开始时，用户通常只知道开始日期；要求填写结束日期会迫使用户把“进行中”伪装成单日记录，或猜测一个尚未发生的结束日。记录模型因此区分三种状态：进行中、已结束但结束日期不详、已结束且有结束日期；只有最后一种状态拥有精确的 Period duration。

## Considered Options

- **继续强制填写结束日期**：拒绝。它阻断真实场景，或把未知事实伪装成已知事实。
- **用开始日作为临时结束日**：拒绝。它无法区分单日经期和仍在进行中的经期，并会污染时长统计。
- **按典型经期长度自动补结束日**：拒绝。预测可以辅助展示，但不能写入用户没有确认的事实。
- **保存显式状态，结束后由用户回填**：采用。它保留事实边界，也让日历能区分当前进行中和历史上结束日期不详。

## Consequences

- 进行中记录在日历上投影为开始日至今天；结束日期不详的记录只投影已知开始日。
- 未完成记录不计入平均时长，进行中的开始日仍可参与周期起点预测；预测结束日只能使用已知历史、用户设置或默认值。
- 新增表单默认进行中，填写结束日期完成同一条记录；同一 Room 的 period stream 只允许一条进行中记录。
- 同一 Room 的进行中唯一性由云端写入路径作为最终约束，客户端重复点击和并发冲突都不能产生第二条进行中记录。
- 旧数据若缺少结束日期按结束日期不详兼容，不自动推断进行中或补写日期；重叠记录不在本决策中合并或硬阻止。
